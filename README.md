# 梱包資材総合ツール (Python / SQLite版) — VER4.8.17

Excel VBA + Access で作られていた梱包資材管理ツールの Python 移植版です。
画面は **Flask + HTML/CSS/JS**、業務ロジックは Python、データは SQLite。
追加で入れるのは `Flask` と `waitress` の2つだけで、フロント側のビルド工程
(npm / webpack)は持ちません。

VER4.0.0 から **デスクトップ版**(`梱包資材総合ツール.exe`、Rust/Tauri の外枠)で動きます。
**ポートを使わず**、窓の中の画面と Python を標準入出力でつなぎます。業務ロジックは
Python のまま。ブラウザ版(`Start.vbs`)も予備として残っています。
作りは [`docs/デスクトップ版.md`](docs/デスクトップ版.md)。

移植済みの業務ロジック(選定・配置・疲労度・保護材・特殊モード・帳票)は
以下の節に範囲を書いてあります。

### ボード自動選定の実装範囲

`packaging_tool/board_selection_algorithm.py` に移植済み。
`auto_select_boards()` が VBA `AutoSelectBoards` に相当するハブで、
下用選定 → 上用選定 → 丈カット再計算 の順に実行する。

**下用**: 1枚物優先 / PASS1(通常モード) / PASS1.5競合選定(疲労度モード) /
PASS2 / PASS3 / 各種強制追加 / `CanCoverWithFill` /
`AdjustOrientationForCoverage` / `RunWidthFillPhase` /
`SimulateLowerWidthFill` / 丈補填反復ループ /
`ApplyLengthFillWidthCorrection` / 主ボードで丈カバー済み時の丈補填削除 /
丈不足強制追加 / 代替ボードリトライループ /
狭幅パレット選定+専用補填 / カット前提選定

**上用**: 上下共用モード(ザラ板等) / プロテックモード(1P1216の-10mm許容を含む) /
主ボード選択(製品幅基準・strict) / 幅補填(不足が80mm超のときのみ) /
丈合計計算 / 丈補填フェーズ(丈残400mm超なら主ボード+1) /
狭幅選定 / カット前提選定(`SelectUpperBoardsWideCut`)

**共通**: `RecalcLengthCutInfo`(丈カットは丈オーバー時に最後の1枚だけ
発生するという業務ルールのSSOT)

選定アルゴリズムはVBAの全段階を移植済み。最終段として次を行う:

- **下用: 幅補填行の丈カバレッジ再確認** — 幅補填として足したストリップが
  主ボード列と同じ長さまで伸びていないと途中で途切れるため、まず同種の
  追加(最大4枚)で、足りなければ別の小型ボードで埋める(最大5回)
- **上用: 丈不足強制追加** — 丈合計が製品丈に3mm超足りない場合、
  「ギャップ以上・ギャップの3倍以内」の小型ボードを1種類足す。
  適当な在庫が無ければ主ボードを `ceil(不足/主ボード有効丈)` 枚増やす
- **上用: 補填ボードの幅不足を30/50/100mmで補填** — 補填行が製品幅に
  届いていなければ小型ボードを脇に敷く。在庫が無い、または必要枚数が
  4枚以上になる場合は、その行を捨てて主ボードを1枚増やす

### 自動配置の実装範囲

`packaging_tool/placement_algorithm.py` に移植済み。
`auto_place_boards()` が VBA `AutoPlaceBoards` に相当するハブで、
下用 → 上用 の順に配置する(上下は別レイヤなので互いに重なってよい)。

座標系はVBA踏襲で **X = 丈方向 / Y = 幅方向**。
`PlacedBoardModel.width` はY方向、`length` はX方向の寸法を表す。

**位置探索** (`TryPlaceSingleOrientation`): パレット内20mm刻みの粗探索 →
既存ボード右端への5mm刻みスナップ(下用のみ) → 最良位置±20mmの1mm刻み
細探索、の3段階。評価関数は `x + y`(左上ほど良い)。

**配置ループ** (`PlaceBoardsFromList`) は2パス構成:

- pNum=1: 主ボード(向きは`TryPlaceInsidePalette`が決め、2枚目以降に引き継ぐ)、
  カット前提、Y積み。完了後に丈補填(`PlaceLengthFillBoards`)
- pNum=2: 幅補填を`TryPlaceYCompanion`で主ボード列の下端に敷く
  (幅が最も足りない主ボードを基準に、行が埋まったら次の行へ送る)

**上用専用**: `TryPlaceUpperWithYOffset`(Y固定でX方向のみ走査) /
`TryPlaceUpperLengthFill`(Y=0の主ボード列の右端に継ぎ足し) /
`CanPlaceAtWithYLimit(AndXBound)`

**その他**: `GetEffectiveTag`(タグが失われた場合の推測復元) /
`SortFillBoards`(幅補填を丈補填より先に配置するための並べ替え) /
`PlaceNarrowPaletteBoards`(狭幅パレット。位置探索を使わず
センタリングしたY座標から積み上げる)

#### あえて踏襲したVBAの癖

元ツールと配置座標を一致させるため、以下はVBAの挙動をそのまま再現している
(直し方はコード内のコメントに記載):

- 上用の2種類目以降は`TryPlaceUpperWithYOffset`で配置されるが、VBA版は
  そこで「最後に置いたボード」の記録を更新しない。そのため次のYオフセットは
  そのボード自身の幅ではなく**1つ前のボードの幅**で進む。
- 下用の配置可否判定にはX方向の上限が無く、既存ボード右端へのスナップ探索も
  パレット丈で止まらない。選定枚数が過剰だとパレットからはみ出して並び続ける
  (枚数を適正に決めるのは選定フェーズ側の責務)。
- 丈補填の配置前に行う重なりチェックは、起点が「同カテゴリ全ボードのX右端の
  最大値」である以上、原理的に成立しない防御的コード。

#### VBA側のデッドコード(移植対象外)

以下7つは呼び出し元が存在しないため移植していない。

| 関数 | 備考 |
|---|---|
| `TryPlaceLowerLengthFill` | 下用丈補填 → `PlaceLengthFillBoards`に統合済み |
| `TryPlaceLowerWidthFill` | 下用幅補填 → `TryPlaceYCompanion`に統合済み |
| `TryPlaceLowerFill` | 下用補填(旧世代) |
| `GetLowerRemainingWidth` | 上記の補助 |
| `GetLowerRemainingLength` | 上記の補助 |
| `SortBoardsByArea` | 面積順ソート(配置順の決定に使われていない) |
| `TryPlaceSpecificRotation` | 回転指定配置 → `TryPlaceWithFixedRotation`に統合済み |

下用の補填配置は実際には `PlaceLengthFillBoards`(丈補填)と
`TryPlaceYCompanion`(幅補填)が担っており、どちらも上用・下用の両方に
対応している。上記は「カテゴリ別に分かれていた旧実装」が共通化された
あとも残されたもの、と読める。

**判定の根拠**(数が多いので機械的に検証した):

1. 7つとも `Private` 宣言。VBAの`Private`プロシージャは同一モジュール内から
   しか呼べないため、探索範囲は`MaterialMasterForm`モジュール
   (エクスポートL3113〜L15938)に限定できる
2. 全3ファイルを大文字小文字を無視して検索しても、出現箇所は
   「自身の宣言・自身の本体(戻り値代入)・デバッグログ文字列・コメント」のみ
3. `Application.Run` / `CallByName` / `Evaluate` による文字列経由の
   動的呼び出しはソース中に1件も無い
4. 同モジュールの全180プロシージャを機械的に解析したところ、参照なしは58件。
   うち45件はイベントハンドラ(`*_Click`等)とPropertyで、これらはExcelフォームの
   ランタイムが呼ぶため参照が無くて当然。残る13件が真のデッドコードで、
   そのうち7件が上表の配置系にあたる
5. 手法の妥当性確認として、実際に呼ばれている`TryPlaceYCompanion`・
   `TryPlaceUpperLengthFill`はデッド判定されないこと、および
   別モジュールから`MaterialMasterForm.GetBestOrientationPublic(...)`と
   呼ばれる`Public`プロシージャが正しく「生存」判定されることを確認済み

なおVBAソースL3380付近には作者による設計コメントがあり、そこでは
`PlaceBoardsFromList`から「`TryPlaceUpperWithYOffset` / `TryPlaceLowerFill`」を
呼ぶ想定と書かれています。しかし実コードには上用の分岐しか存在せず、
対になる下用の分岐は書かれていません。設計意図としては下用にも専用経路が
あるはずだったが未実装のまま、という状態です
(下用は汎用探索で処理されるため機能上の欠落はありません)。

#### 実データによる配置の検証

`PalletPatterns`に残る41通りのパレット/製品サイズすべてで、
選定→配置を通して**例外なし・同カテゴリ内の重なりなし**を確認済み。
在庫ボードの最大辺(2500mm)を超える幅を持つ実在パレット4種
(2550/2552/2660/2710mm幅)についても同様に確認した。

例として パレット1150×2650 / 製品1122×2502 では、主ボード
750×1130 を3枚並べたあと幅1080の主ボードが1枚入り、その下端(Y=1080)に
50mm幅の幅補填が入る。VBAのコメントにある「1080mmと1130mmが混在する
ケースで50mm補填が誤位置に配置される不具合の修正」が意図どおりに
再現できている。

#### 実データによる選定の検証

`PalletPatterns`に残っていた過去の実績パターンと突き合わせた結果:

| パレット | 製品 | 実績(下用) | 移植版の下用選定 |
|---|---|---|---|
| 1280×3150 | 1252×3052 | 1250×2500 ×1, 500×1250 ×1 | 主ボード2種とも一致 |
| 1150×2650 | 1122×2502 | 750×1130 ×3, 660×1310 ×1 | 主ボード 750×1130 ×3 が一致(2枚目以降は相違) |

**注意**: `PalletPatterns`は「過去に保存された実績パターン」であり、
必ずしも現行アルゴリズムの出力と一致するとは限らない(手動で調整された
ものや、アルゴリズム改修前に保存されたものが含まれうる。実際
`使用回数`カラムがあり読込・再利用される運用になっている)。
そのため一致は移植の妥当性を裏付ける材料にはなるが、
不一致が直ちに移植ミスを意味するわけではない。

狭幅パレット(例: 300×2000)・カット前提(在庫最大幅を超える製品)の
各経路についても、実データで例外なく候補が選定されることを確認済み。

### 資材選択タブのコントロール配置について

VBAソースの `CreateSimpleUI` には
**「認知心理学: 一貫した間隔定数（ゲシュタルト近接原則）」**というコメントがあり、
コントロールの配置は意図的に設計されている。Python版でも次の設計判断を
そのまま踏襲している(勝手に並べ替えないこと)。

| 設計判断 | 意図 | VBAでの根拠 |
|---|---|---|
| タブ順は作業順 | ロット検索 → 資材選択 → … → 選定ログ | `mpMain.Pages` の 検索(0) / 設定(1) / 選定ログ(2) |
| ロット検索のフレームはデータの流れ順 | 検索条件 → ロット情報 → 引当情報 → 受注情報 | `CreatePage1` の `top` = 4 / 56 / 312 / 452 |
| 左が配置図・右が操作パネル | 視線は左の結果に向き、操作は右に集約する | キャンバス群 `left=10 幅490` / コントロール `left=540` |
| **アングル → 上用 → 下用**の順に描く | 上から見た順序を保つ | `PaletteCanvasAngle` → `Upper` → `Lower` の生成順 |
| **上用ボードを上・下用ボードを下**に描く | 実際の積み重ね順と画面の上下を一致させる(空間的一致) | `PaletteCanvasUpper` → `PaletteCanvasLower` の生成順 |
| 選定リストも上用が上 | キャンバスと並び順を揃える | セクション3=上用ボード、4=下用ボード |
| 上用=赤系 / 下用=緑系 で統一 | 見出し・キャンバス背景・ボード色を同じ色相で対応付ける | `ForeColor` RGB(139,0,0)/RGB(0,100,0)、`BackColor` RGB(255,250,250)/RGB(250,255,250) |
| セクション順は作業順 | パレット → 製品 → 上用 → 下用 → ボード候補 → 管理者 | セクション見出しの番号コメント |
| 実行ボタンの縦並びも作業順 | ボード選定 → 疲労度優先 → ボード配置 → ボードMAP → クリア | `btnAutoSelect`/`btnFatigueSelect`/`btnAutoPlace`/`btnMap`/`btnClearAll` の `top` |
| 「パレットMAP」はパレットサイズ欄の並びに置く | 参照するデータの近くに操作を置く | 適用/ﾊﾟﾚｯﾄMAP が同じボタン行 |
| 管理者エリアは右下に隔離 | 日常操作から離す | `rX = mpMain.width - 15` からの右寄せ配置 |
| 「認証」の手前だけ間隔を倍に | 誤操作防止 | 他は5pxのところ認証だけ10px。`'少し離して誤操作防止'` のコメント |
| 保存ボタンは認証まで無効 | 押せないことを見た目で示す | `btnSavePattern.Enabled = False` → `btnAuth_Click` で `True` + 色を濃くする |
| セクション間マージンを統一 | 近接の原則でグループを認識させる | `secGap = 6` |

この配置の意図は Web 版の画面(`app/templates/selection.html`)にも
そのまま引き継いでいる。上用が上・下用が下、図が左・操作が右、
保存は認証まで押せない ── 勝手に並べ替えないこと。

### 資材選択タブの操作フロー

VBA `MaterialMasterForm` と同じ順序で操作する。

1. **パレットサイズ**を設定(手入力 / 一覧から選択 / 製品サイズからの自動選定)
2. **製品サイズ**を設定(パレットに収まるか検証し、必要なら自動で幅と丈を入れ替える)
3. **候補ボード**の種別を選ぶ(「在庫考慮」をONにすると看板が出ている在庫薄の
   ボードを後ろに回す)
4. **「ボード選定」**(VBA `btnAutoSelect_Click`)で上用・下用を自動選定。
   選定リストには `[主]` `[幅補填]` `[丈補填]` `[カット前提]` のタグが表示される。
   **「疲労度優先」**(VBA `btnFatigueSelect_Click`)を押すと、拠点(L1/HVC/LVC)からの
   取り出しやすさをスコアに織り込んで選定する
   (マップ取得に失敗した場合はVBA同様に通常選定へフォールバック)
5. **「ボード配置」**(VBA `btnAutoPlace_Click`)で配置を実行し、
   左側の2枚のキャンバス(上=上用/製品基準、下=下用/パレット基準)に配置図を描く
6. **「パレットMAP」**(VBA `btnUFMAP_Click`)で簡易在庫タブへ、
   **「ボードMAP」**(VBA `btnMap_Click`)で棚検索タブへ移動できる。
   前者はパレットサイズを検索欄に流し込み、後者は選定済みの上用・下用ボードと
   選択アングルをまとめて渡して、取りに行く棚をハイライトする
   (棚が出ない場合は`ShelfLabelMap`へのラベル対応登録が未実施)
7. 必要なら右下の管理者エリアで**認証** → **「保存」**で実績パターンをDBに登録。
   **「実績検索」**は現在のパレットサイズに一致する過去の実績を一覧表示し、
   選ぶとパレット/製品サイズと選定リストを復元する

### ロット検索タブ

ロット番号を7桁入力すると自動で検索する(VBA `Page1_OnTxtLotNoChanged` と同じ挙動)。
表示は上から 検索条件 → ロット情報 → 引当情報 → 受注情報 で、VBAのフレーム順どおり。

移植した業務ルール:

- **BOX実績寸法への差し替え**: 設計_設備コースに `GFS`/`GCT`/`GSS` のいずれかを
  含むとき、板厚・板幅・板丈をBOX実績の値に差し替え、見出しに
  「【BOX実績寸法】」を出して設計_設備コースを赤字にする
- **包装仕様NOの書き換え**: 製造材質が`*75S` / 製造調質が`T6*` / 用途コードが
  `K434`か`K435` / **製造板厚**(BOX実績に差し替える前の値)が`6.75` / BOXコース、
  の5条件すべてを満たすとき `1P0122` に書き換える
- **引当情報**は引当番号の昇順に並べる
- **EX判定**: `EX_輸出区分`が空でなければEX受注とし、見出しに`EX`を付けて
  資材選択タブの「EXオンリー」絞り込みを有効化する(VBA `SetExOrder`)

資材選択タブへは、確定したロットの**表示中の板厚**(BOXコースならBOX実績)と
EX受注フラグが渡る。前者はパレット検索の5×10業界の強度UP判定に使われる
(VBAが`valLot4`を直接読んでいた箇所に相当)。

### 倉庫送信

パレットサイズ欄の「倉庫送信」(VBA `btnSendToWarehouse_Click`)で、
ロット情報とパレットから発注1行を組み立て、確認ダイアログを経て
`資材パレット注文管理`に登録する。

- 品名は「業界　記号　幅x丈」。記号は`FilterPalSym`相当のフィルタで
  G1/G2/A2〜A8 を落とす
- **発注コードと単位はパレット一覧の選択行から採る**ため、一覧で行を
  選んでいないと送信できない(その旨を明示するメッセージを出す)
- 発注数は`CalcTotalPackages`相当の梱包数見積り。引当調整NOが混ざる場合や
  比重が無くkg梱包がある場合は計算不可として空欄で送る(VBA踏襲)
- 厚は表示中の板厚(BOXコースならBOX実績)、**幅・丈はロットの板幅・板丈**。
  製品サイズはパレットに載せる都合で回転していることがあり、それを送ると
  倉庫側に板の寸法が入れ替わって伝わるため(VBA `GetLblLotCaption(5)/(6)`)

1P0113(裸梱包)モードのときは、パレット1行ではなく**溝切角材と松板の2行**を
送る。詳しくは次節。

### モードの網羅状況

VBA版にあるモードと、Python版での対応は次のとおり。

| モード | 種別 | 状態 | Python版での場所 |
|---|---|---|---|
| 1P0113(裸梱包) | 自動 | 実装済み | `special_packaging.py` + 資材選択タブの1P0113パネル |
| プロテック | 自動 | 実装済み | `special_packaging.protec_state` + `select_upper_boards` |
| EXオーダー | 自動 | 実装済み | `set_ex_order`。モード帯と一覧の色分け |
| 上下共用(ザラ板等) | 自動 | 実装済み | `apply_hosozai` + `select_upper_boards` の共用分岐 |
| 1P1216限定 | 自動 | 実装済み | `PROTEC_1P1216_TOLERANCE`(幅許容-10mm) |
| 2山積 | 手動トグル | 実装済み | 「2山積みモード」。Pass17〜20を含む |
| 疲労度優先 | 手動トグル | 実装済み | 「疲労度優先」。ボード選定とアングル自動選定の両方に効く |
| 在庫考慮 | 手動トグル | 実装済み | 「在庫考慮」。候補一覧に「▲薄」 |
| 管理者 / 拠点設定 | 手動 | 実装済み | 管理者エリアの「認証」「拠点設定」 |

頂いたモード一覧と実際のVBAコードで**食い違っていた点**が2つある。
コードのほうに合わせてある。

- **プロテックの着火条件**: 一覧には「納入先が特定得意先の時」とあるが、
  VBAの`CheckAndSetProtecMode`は `cond1 = False` として
  「ｶ)ﾏﾂｼﾀｼﾖｳﾃﾝ判定は廃止」と明記されており、実際には**包装仕様NOだけ**で
  判定している。Python版も包装仕様NOのみで判定する
- **位置設定モード**: 一覧には「MAP上の棚ラベル位置をマウス操作で編集可能に」
  とあるが、VBAの`mPositionSetupMode`は`ShowPositionSetupOnForm`が出す
  **拠点(L1/HVC/LVC)の登録画面**で、棚ラベルの座標編集機能はVBAソースに
  存在しない。Python版も拠点の登録として実装している
  (棚ラベルと棚区画の対応付けは、別途「資材配置(棚検索)」タブの
  ラベル対応登録パネルで行う)

### 包装仕様NOで切り替わる特殊モード

ロットを確定すると、受注の包装仕様NOによって資材選択タブが3通りに分岐する
(VBA `SearchAndDisplay` 末尾の `Apply1P0113Mode` → `GetUpperPartMaterial`
→ `CheckAndSetProtecMode` の順を踏襲。互いに独立ではなく、この順で
呼ばれる前提の状態機械なので順序を変えてはいけない)。

判定とマスタ参照は `packaging_tool/special_packaging.py` に切り出してあり、
tkinterに依存しないので単体で検証できる。

#### 1. `1P0113` = 裸梱包モード

パレットもボードも使わず、溝切角材と松板だけで組む。
パレットサイズのセクションを丸ごと隠し、**同じ位置に**1P0113パネルを出す
(VBA `ShowPaletteSizeSection(False)` + `Create1P0113UI`)。
「1番目のセクション = そのロットで決めるべき資材」という位置の意味づけを保つため、
別の場所には出さない。

- **松板の丈(A値)**: 製品丈 1〜949 はその値、〜1800 は950、〜2400 は1600、
  それ以上は2330
- **溝切角材の丈**: 製品幅 + 10mm
- **必要数**: 溝切角材は製品丈 〜1800で2本 / 〜2400で3本 / それ以上4本、
  松板は常に2枚。どちらも乗数スピン(1〜10)倍する
- **乗数の初期値**は総梱包数(`CalcTotalPackages`)。製品サイズが変わったときだけ
  入れ直すので、利用者が手で変えた値をサイズ据え置きの再読込では潰さない
- 資材は`松板角材`テーブルから「品名・厚・幅が一致し、丈帯が対象値を含む」行を引く
  (角材は 75x75、松板は 24x120 固定)
- 松板/角材のラベルをクリックすると、その資材のフル情報(寸法帯・コード・単位)に
  情報行が切り替わる(VBA `Show1P0113LabelTip`)

1P0113中は製品サイズが資材そのものを決めるので、`Load1P0113Materials`と同様に
**入力欄の値を直接読む**。パレットが無く「セット」(パレットに収まるかの検証)を
通せないため、確定済みの製品サイズではなく入力欄を見るのが正しい。

**強制1P0113トグル**(VBA `lblForce1P0113`)を操作パネル最上部のモードバーに置いた。
包装仕様NOが取れない/誤っているロットでも裸梱包として組める逃げ道で、
ONにした瞬間にモードへ入り、OFFに戻すと現在の包装仕様NOで判定し直す。
セクションの中ではなくモードバーに置いてあるのは、パネルの中に入れると
1P0113中はそのパネルごと消えて解除できなくなるため。

**倉庫送信は2行**になる。品名・発注コード・単位は表示用のフル情報文字列から
切り出す(VBA `Parse1P0113Info`)ので、**品名に載る丈はマスタの丈帯**
(例 "1001-1999")であって実際の切断長ではない。発注コードが帯ごとに
分かれているため帯の表記で足りる、というVBA側の判断をそのまま踏襲している。

なお実データでは溝切角材の丈帯が 0-2999 までしか登録されていないため、
製品幅がちょうど3000mmのときだけ「該当なし」になる(VBAでも同じ)。
その場合は送信を止めて理由を出す。

#### 2. `1P1216` / `1P1125` / `1P1211` = プロテックモード

ボード種別を自動で「プロテックボード」に切り替え、上用ボードは下用の主ボードと
同サイズを強制する(有効幅が許容内のとき)。許容は **1P1216 だけ -10mm**、
他のプロテックは -80mm。1P1216(ｺｰﾐ金属)は本来-20mmだが、切断精度を考慮して
-10mm(片側-5mm)にしてある、というVBAのコメントをそのまま引き継いでいる。

プロテックを抜けるとボード種別は既定の「ハードボード」に戻る。
モードバーには VBA `DynamicTip_ProtecMark` と同じ
「【プロテックボードオーダー選択中】」を青地の白文字で出す。

#### 3. 保護材選定によるアングルの要否

`GetUpperPartMaterial`(包装仕様NO・材質・調質・用途コード・板厚/板幅/板丈)で
使用保護材を引き、**アングル以外に確定したときだけ**アングル関連の
コントロール(配置図・候補一覧・選択リスト)を隠す。
`""`(対象外)と`"一致なし"`(マスタ未登録)はどちらも安全側に倒して出したままにする
(VBA `ShowAngleControls` と同じ判断)。

確定した保護材は選定にも渡り、アングルでも「一致なし」でもなければ
**上下共用モード**(上用=下用と同サイズ)になる。ただしプロテック中は
上下共用が抑止される(VBAの条件 `Not mIsProtecMode And ...` を踏襲)。

上下共用のときは画面も切り替わる。**上用のキャンバス・見出し・選定リストを
まとめて隠し**、下用の見出しを「【上下共用ボード配置】」に変える
(VBA `ShowAngleControls` が `PaletteCanvasUpper` と
`lstSelectedBoardsUpper` を同時に隠し、下用キャンバスを上用の位置へ
移動していたのと同じ意図)。

### 手動で切り替えるモード

- **疲労度優先**(VBA `btnFatigueSelect_Click`): 押しっぱなしのトグルで、
  ONのあいだは**ボード選定とアングル自動選定の両方**が疲労度を見る。
  ロットを切り替えても解除されない。ON時は紫(VBAの`RGB(180,100,255)`)。
  アングル側は丈ごとに最寄り棚の距離+長さから疲労度を出して選定に渡す
  (`location_service.build_angle_fatigue_map`)。棚が引けない場合は
  通常の優先順位に落とし、その旨を選定ログに出す
- **2山積**: パレット検索が2山前提になる。幅2山は奇数桁のパレット限定(スカシは桁数不問)、
  丈2山はスカシ・タイト業界で脚3本以上、専用のPass17〜20が加わる。
  決めたパレットの当たり方で**2山の向き**(幅/丈)を覚え、製品サイズの確定でその向きを
  2倍して**2山分を1つの製品として**扱う(上用の選定・配置・カバー表示・切断依頼がすべて
  2山分で動く)。入力欄は1山分のまま(VER3.5.6)
- **在庫考慮**: 看板テーブル群を横断して在庫薄を判定し(`BuildBoardStockMap`)、
  候補一覧に「▲薄」を出して在庫のあるボードを優先する
- **1P0113強制**: 上記の「強制1P0113トグル」。**新しいロットを読むと
  自動で解除される**(VBA `ClearForNewLot`)。疲労度優先と在庫考慮は
  手動トグルなのでロット切替でも解除しない

#### 資材展開(ロット検索 → 資材選択)

ロット検索タブの「資材展開」(VBA `btnHB` / `Page1_OnBtnHBClick`)で、
製造板幅・板丈を製品サイズの入力欄に入れて資材選択タブへ移る。
**「セット」までは押さない**のがVBAの挙動で、パレットに収まるかの検証
(回転の要否を含む)は利用者が自分で「セット」を押して行う。
1P0113中は資材だけ引き直す。

### 帳票の印刷

`packaging_tool/printing.py` が、VBAの「Excelシートに書いて`PrintOut`」を
置き換える共通基盤。**HTML + 印刷用CSS**を生成し、既定ブラウザで開いて
印刷する(追加インストール不要)。

VBAの`PageSetup`はCSSの`@page`にほぼ1対1で対応する:

| VBA | CSS |
|---|---|
| `.Orientation = xlLandscape` | `@page { size: A4 landscape; }` |
| `.TopMargin = 0` 等 | `@page { margin: 0; }` |
| `.FitToPagesWide = 1` | 幅100%のテーブルで組む |
| `.PrintArea` | `.sheet` ブロック1つ = 1ページ |

```python
report = printing.Report(title="Lot貼付用",
                         setup=printing.PageSetup(orientation=printing.LANDSCAPE))
report.add_sheet(printing.label_pairs([("材質", "A5052"), ("厚", "3.000")]))
printing.print_report(report)              # ブラウザで開く → Ctrl+P
printing.print_report(report, direct=True)  # OSの印刷動詞へ直接
```

`direct=True` は Windows では `os.startfile(path, "print")`、
それ以外は `lpr` を使う(VBA `PrintOut Preview:=False` に相当)。
ブラウザの「PDFとして保存」で控えも残せる。

**注意**: 貼付用ラベルのように現物と寸法を合わせる帳票は、ブラウザの
余白設定に左右されるため実機での確認が必要。既存のExcelテンプレートの
見た目を厳密に保ちたい場合は、`open_with_system_print` に .xlsx を渡して
Excel側に印刷させる選択肢もある。

### 帳票の中身(Lot貼付用 / 切断依頼書)

`packaging_tool/reports.py` が、VBAの`CreateLabelLayout` /
`CreateCuttingRequestForm` が組んでいた紙面をHTMLで再現する。
HTML文字列を返すだけでtkinterに依存しないので、GUIなしで内容を検証できる。

セル結合(`Merge`)は `colspan`/`rowspan` にそのまま対応させ、列幅・行高も
元シートの値(文字数・ポイント)から比率・mmに換算している。ただし
「結合してから内側の罫線を消して2段組みにする」というVBAの組み方
(切断依頼書の切断サイズ欄)だけは、HTMLでは入れ子のブロックで組んでいる
(見た目は同じ)。

#### Lot貼付用 (`btnPrint`) — A4横・余白0

左半分(A:J)を7行、右半分を「見出し+値」で組む。VBAは最後に
`ws.Columns("K").Insert` で仕切り列を1本足すので、その位置に縦罫線が入る。

- 左: VC表 → WVC → 製品寸法 → パレット(業界 記号 / 幅×丈) → 梱包数+単位 → LotNo
- **VC表が空のときは「K」の丸印**を2〜3行にまたがって描く(VBA `DrawCircleK`。
  枠線3pt・文字は円の高さの80%)
- 右: 用途/材質/オーダーサイズ + 引当欄(縦結合) → 宛先3行 → 単位・コード →
  納送コメント(赤) → 工場コメント(青)
- 引当が3件以上だと入りきらないので7ptに落とす(VBA踏襲)
- **1P0113では**パレット欄が「裸梱包 + 溝切角材N本 + 松板N枚」に替わり、
  梱包数の行は出さず、右の単位・コード欄が角材/松板の明細セルに替わる

#### 切断依頼書 (`btnCutRequest`) — A4縦・余白1cm

表題は「拠点 ボード種別 切断依頼書」(拠点`L1`は`L-1`と書く)。
切断サイズ欄は上下2段で、上段が「幅カットのみ」、下段が「幅+丈カット」。

- 通常モードは**上用・下用**の2セクション。各行に切断サイズ・元サイズ・
  「1梱N枚」・総枚数(1梱の枚数×梱包数)を出す
- **プロテックモードは上下を分けず**、上用の主ボード1種類だけを見る。
  幅カットは有効幅が製品幅を超えるときだけ発生し、切断幅は
  製品幅 - 許容(**1P1216は10mm**、他のプロテックは80mm)。
  丈方向のはみ出しが100mm以下なら丈カットは不要とみなす
- 幅補填・丈補填のボードは切断対象外(VBA `GetCutSizeInfo` が飛ばす)
- カットの記録が1つも無ければ「依頼は不要」と案内して帳票を出さない

### 拠点設定

管理者エリアの「拠点設定」(VBA `btnPositionSetting_Click`)で、拠点(L1/HVC/LVC)を
登録する。**拠点は複数の機能が参照する共有設定**である点が重要:

- 疲労度マップの構築(`BuildFatigueMap3`)
- アングル選定の疲労度(`CalcAngleFatigue`)
- 棚検索(`frmLayout`)

VBAはこれを1つのレジストリ値(`GetSetting("梱包資材管理","Config","Position")`)で
持っていたので、Python版も画面ごとに別々の値を持たせず
`packaging_tool/user_settings.py` を唯一の出どころにしている
(レジストリの代わりに`data/user_config.json`へ保存)。
資材選択タブと棚検索タブのどちらで変更しても、もう一方に即座に反映される。

### 選定リストの手入力

手動で候補ボードを選定リストに追加することもできる(その場合は狭幅パレット
フラグを引き継がないため、通常の配置経路で描画される)。
選定内容を変更すると配置図は自動的にクリアされ、古い図が残らないようにしている。

#### 実績の保存/読込について(スナップショット)

保存するのは**配置を承認した画面の状態そのもの**(VBA `modPatternStore`)。
ヘッダ(パレット・製品・ボード種別・配置方式・狭幅・保護材・アングル・
プロテック確定値・LotNo・拠点)と、明細3種(選定リスト**タグ込み**・
置いたボード1枚ずつの座標・カット)を1組で持つ(`packaging_tool/pattern_store.py`)。

- **読込は計算し直さない。** 保存したときの選定と配置図がそのまま戻る。
  ロットから決まる状態(プロテックか・保護材)は上書きせず、食い違えば知らせる
- **配置のあとで変えたら保存しない。** 配置した時点の内容と見比べる
- 配置方式(通常 / 別案A〜C)も残り、一覧のボード構成に `[通常]` のように出る
- **全端末で共有する。** 保存・読んだ回数・削除は取り込み元(梱包資材マスタ)へ
  書き戻し、取り込みで受け取る(`packaging_tool/pattern_sync.py`)。
  まだ送れていない実績は一覧に「この端末だけ」と出る
- 表の名前と保存形式は VBA と同じ(`config.TBL_PT_*` = `パレット実績ヘッダ` /
  `パレット実績選定` / `パレット実績配置` / `パレット実績カット`、`PT_FORMAT_VER` = 2)。
  **VBA が保存した実績も一覧に出て、そのまま読み込める**

旧版の実績(`PalletPatterns`)は形が違うので一覧には出ない
(VBA も `PalletHistoryModule_v2` を削除している)。表そのものは画面比較
(`scripts/compare_ui.py`)の元データとして取り込みを続ける。

タグが空のボード(手動追加だけで配置したとき等)は、配置側の
`GetEffectiveTag` が推測して補う。推測の基準は**選定ロジックと同じ許容値**
(上用 80mm / 下用 11mm。製品幅 − 主ボード幅)。

管理者パスワードは `packaging_tool/admin_password.py` が持つ。役目は
VBA版と同じ**保存ボタンの誤操作を防ぐUIガード**で、誰がその端末を
使えるかを決めるのは `アクセス権限` マスタのほう(`access_control`)。

- **現場で変えられる。** 設定画面の「パスワード」タブから変更する。
  変えられないパスワードは実質「変えない」と同じで、人が入れ替わっても
  直せないままになる
- **平文では持たない。** 変えた値は PBKDF2 で撹拌して
  `data/user_config.json` に入る。配布はフォルダごとコピーなので、
  設定ファイルはそのまま持ち出せる ── UIガードとはいえ平文で置く理由が無い
- **一度も変えていない端末では、これまでどおり** `config.ADMIN_PASSWORD`
  (環境変数 `PACKAGING_TOOL_ADMIN_PASSWORD` で上書き可)が通る。
  入れ替えただけで認証が通らなくなる、を作らない

#### 配置図の描画

描画に必要な計算(スケール、中央寄せ補正、カット検出、色分け、キャプション)は
`packaging_tool/placement_render.py` に切り出してあり、**描き方は知らない**ので
画面なしで単体テストできる。実際に描くのはブラウザ(`svgplan.js` が SVG を組む)。

- 枠は基準サイズ(下用=パレット、上用=製品)。キャンバスの90%に収まる倍率で
  縮小し、主ボードのバウンディングボックスを使って中央寄せする
  (枠からはみ出している場合は補正せず、はみ出しをそのまま見せる)
- ボード色はVBAと同じ 下用=薄緑 / 上用=薄赤。画面上15px未満で文字が入らない
  ボードは色分けに切り替え、30mm=青 / 50mm=緑 / 100mm=紫、
  それ以外は画面上の厚みで3段階に色を変える。使われた細ボードは
  キャンバス左下に凡例として表示する
- カットがあるボードには右端/下端に赤いカットライン、切り落とされる部分に
  オレンジのカットゾーン(`|||` / `===`)を描く。補填ボードはカットが無ければ
  カット表示を省略する(VBA踏襲)

### アングル配置図の実装範囲

`packaging_tool/angle_render.py` に移植済み(VBA `DrawAngleBoards`)。
パレットを真横から見た断面として、**アングルバー(上) / パレット面 / 脚(下)**
の3段を左カラムの一番上に描く。製品の左右端は赤い縦線で示す。

- 基準寸法はパレット丈(未設定なら製品丈)。キャンバス幅の88%に収める
- 脚は`PalletMaster`の脚数から等間隔に配置(取得できないときは2本)
- バーの配置は本数で変わる:
  - 1本: 製品左端に置く
  - 2本: パレットに収まるなら中央揃えで突き合わせ、収まらないなら左端+右端に寄せ、
    上下2段に分けて重なりを見せる
  - 3本以上: 左から順・右から逆順に並べ、奇数本なら中央の1本を左右の内端の
    中点に置く。中央のバーは上段かつ最後に描く(前面に出す)
- 1本をカットして使う場合(`select_angles`の`need_cut`)は、切り落とす側を
  グレーの廃材ゾーン+赤いカット線+「カット N->Mmm」で示す
- 合計丈が製品丈を超える場合は「ｱﾝｸﾞﾙ被りNmm」を中央上部に表示
  (2本でパレットに収まるときは被り扱いにしない)

操作は右パネルの「アングル」欄から:
**アングル追加**(候補から手動追加) / **アングル自動**(`btnAngleAuto_Click`。
製品丈・パレット丈・脚数から本数と組み合わせを選定) /
**アングル配置**(`btnAngleDraw_Click`。図を描画) と、
【上用ボード】の右隣にある「選択アングル」欄の**削除**。

VBA同様、自動選定しただけでは描画されず「アングル配置」を押して初めて図が出る。
手動で追加/削除した場合はカット前提の情報が失われるため、廃材表示は消える。

### 選定ログ(旧`txtUserLog`)

「選定ログ」タブで、パレット検索が**なぜその結果になったか**を1行ずつ確認できる。
パスごとの探索寸法・候補・決定理由に加え、除外されたパレットの理由を
`範囲外(W:min~max L:min~max)+属性(業界)+桁数偶数(N)` の形で表示する。
2山モードで「サイズも属性もOKなのに桁数が偶数だから落ちた」行は、
「惜しい」上位3件に埋もれないよう別枠で全件表示する。

VBAには無い追加として、探索前に落ちている行の件数と、
**適合範囲が`min>max`で逆転しているマスタ行**の件数を先に知らせる。
単に「範囲外」と出すと原因がマスタ側にあることが分からないため。

この逆転行は実データに70件あり、原因は適合範囲の再計算
(`RunUpdatePalletAll`)が上限を「寸法 - 10」で求めていたことだった。
幅2.5mmのような異常値の行では `巾適合max = -8` となり、
`巾適合min = 300` を下回って「何を検索しても絶対にヒットしない行」に
なっていた。現在は下限と対になる段階表(`calc_haba_max`/`calc_dake_max`)から
引くよう修正済みで、全域で `min <= max` が保証される
(`test_fit_range_can_never_invert` で固定)。

既存DBの逆転行は、受入を1件行えば `recompute_fit_ranges` が
全行を再計算して解消される(VBA同様、受入のたびに全件再計算する)。
今すぐ直したい場合は次を実行する:

```bash
python3 -c "from packaging_tool import db, pallet_service; \
  conn = db.get_connection(); print(pallet_service.recompute_fit_ranges(conn))"
```

### `frmLayout`(資材配置の可視化)の移植メモ

調査の結果、`frmLayout`は「配置図を描画するフォーム」ではなく、Excelフォーム上に
デザイン時から固定配置された棚ラベル(位置固定のLabelコントロール)と、
`BoardMaster`/`CornerboardMaster`の「データラベル」列(棚ラベル名をカンマ区切りで
参照)を突き合わせて「必要な資材が最寄りのどの棚にあるか」を検索し、
取り出しやすさを疲労度スコアとして計算する仕組みでした。
棚の名前(`lblItem4`など)は`BoardMaster`のデータから分かりますが、
各棚の**画面上の物理座標**はExcelフォームのデザイナー情報(バイナリ)にのみ
存在し、VBAのテキストエクスポートには含まれていなかった。

ユーザーから実際のフォームのスクリーンショットを提供してもらい、そこに
写っている棚(L1/HVC/LVC/AIM/SVC/中板18-22/小板13-16等)のおおよその
画面上の位置を`packaging_tool/floor_plan.py`に書き起こして解決した
(拠点からの相対的な距離関係が合っていれば疲労度スコアとしては
実用上問題ないため、ピクセル単位の厳密な再現はしていない)。

ただし「どのデータラベル(`lblItem4`等)がどの棚区画か」までは
スクリーンショットの色分けだけでは復元できなかったため、
`ShelfLabelMap`テーブルと資材配置タブの管理パネルから手動登録する
運用にしている(未登録のラベルは棚検索の対象外になるだけで、
他の処理は妨げない)。

### 起動と停止

**ダブルクリックするのは `Start.vbs` の1つだけです。**

| ファイル | 何をするか |
|---|---|
| **`Start.vbs`** | 通常の起動。コンソールを出さずにブラウザが開きます |
| **`start.bat`** | 診断用の起動。**起動しないときはこちら**。経過と理由がコンソールに出ます |
| **`stop.bat`** | 停止。このアプリだけを止めます |

現場モードで開くか資材モードで開くかは、**この端末に許されたモード**で
決まります(`アクセス権限` マスタ)。両方の権限がある端末は、画面の上の帯で
切り替えられます。

> 以前は資材用に `Start_資材.vbs` を別に置いていました。押すものが2つあると、
> 資材の端末で現場のほうを押したときに「発注一覧が出ない」となり、
> 権限の問題として調べることになります。どちらで開くかは端末が知っているので、
> 押すものを分ける必要はありません。

コマンドから使う場合:

```bash
python start_app.py                      # 端末に許されたモードで開く
python start_app.py --mode material      # モードを指定する(旧名 warehouse も可)
python start_app.py --check              # 実行環境の確認だけ(診断用)
python process_manager.py --status       # 動いているか見る
python process_manager.py --all          # 現場・資材の両方を止める
```

`start.bat` は引数をそのまま `start_app.py` へ渡します。両方の権限を持つ
端末で2つのモードを並べて開きたいときは `start.bat --mode material` を使います。

- 同じアプリを二重に起動しようとすると、**新しく起動せず既存の画面を開きます**
- 同じアプリを**ブラウザのタブで2枚**開いたときは、**操作できるのは最後に
  開いた1枚だけ**です。作業状態(Lot・パレット・選定)はプロセスに1つしか
  無いので、2枚から触ると片方の内容でもう片方の操作が通ってしまいます。
  古いほうには覆いが出て、「このタブで続ける」で取り戻せます
  (`packaging_tool/screen_lock.py`)
- ログ・作業ファイルは **`%LOCALAPPDATA%\PackagingTool`** に置かれます
  (アプリ本体を共有フォルダに置いても、端末ごとに分かれます)
- **DB・設定・配置図はアプリのフォルダの中の `data\`** です
  (`packaging_tool.db` / `user_config.json` / `floor_plan.json` / `pallet_map.json`)。
  `%LOCALAPPDATA%\PackagingTool\data` も作られますが、**まだ使っていません**
  (`app_config.py` の「Phase 0」)。版を入れ替えるときは `data\` を持っていくこと

移行できている画面(**7画面すべて**・Phase 7 まで):

| URL | 画面 |
|---|---|
| `/lot` | ロット検索(絞り込み一覧 → 1件で自動確定 → 詳細モーダル) |
| `/selection` | 資材選択(パレット・製品サイズ・ボード選定・アングル・配置図・帳票・倉庫送信) |
| `/inventory` | 簡易在庫(位置マップ・検索・受入・払出) |
| `/warehouse` | 倉庫連携(現場=発注・取消 / 資材=確認) |
| `/layout` | 棚検索(配置図・最寄り検索・配置編集) |
| `/log` | 選定ログ(差分取得・種別で絞り込み) |
| `/settings` | 設定(取り込みと反映・いまの状態・マスタ管理・置き場所・動作・パスワード・よく使う条件・ボード人気度・最近の結果) |

現場モードと資材モードは同じデータベースを見ます。違うのは、
**資材でしかできない操作(確認・取消)が、権限の無い端末には存在しない**
ことです(`アクセス権限` マスタ。詳細は [`docs/設計.md`](docs/設計.md) §3.5)。
モードは画面右上で切り替えられますが、選べるのは権限のあるモードだけです。

**取り込みはブラウザを閉じても続きます。** 開き直すと設定画面に
進捗が戻ります。実行中に「終了」を押しても、処理が終わるまで止まりません。

#### 起動しないとき

まず **`start.bat`** を実行してください。理由がコンソールに出ます。

| 症状 | 原因と対処 |
|---|---|
| 「サーバを起動できませんでした」 | 表示されるメッセージが「繋がりません」か「応答が返りません」かで原因が分かれます。後者はプロキシ設定に `127.0.0.1` の除外が無い場合が典型です(ブラウザ側の除外も確認してください) |
| ダブルクリックしても何も起きない | `Start.vbs` だけをデスクトップにコピーしていないか確認してください。アプリ一式のフォルダの中から実行します(ショートカットは可) |
| 文字が化ける | `.bat` / `.vbs` を UTF-8 で保存し直すと化けます。**CP932(Shift-JIS)+ CRLF** のままにしてください |
| 「必要なパッケージが入っていません」 | 表示されたコマンドをコマンドプロンプトで実行してください |

`start.bat` はプロキシ設定も表示します。社内PCでは、自分自身
(`127.0.0.1`)への通信までプロキシへ送られて失敗することがあります。
アプリ側はプロキシを経由しないようにしてありますが、ブラウザ側の
除外設定は環境に依存します。

## 使い方

> 現場の方向けの手順書は **[`docs/はじめに読む_起動と使い方.md`](docs/はじめに読む_起動と使い方.md)**
> にあります。起動・データ取り込み・画面の流れ・印刷・モードの見分け方まで
> 一通り書いてあるので、まずはそちらをどうぞ。

初回起動時にDB(`data/packaging_tool.db`)が自動作成されます。
起動は `Start.vbs`(コマンドからは `python start_app.py`)です ──
**`python -m packaging_tool` では起動しません。** tkinter版だったころの
入口で、Web版には `__main__.py` がありません。

サンプルデータ付きでDBを作り直したい場合:

```bash
python3 scripts/init_db.py --seed
```

DBファイルの場所は環境変数で変更できます(共有フォルダに置く場合など):

```bash
PACKAGING_TOOL_DB_PATH=/path/to/shared/packaging_tool.db python start_app.py
```

### 開発中に取り込み元を別の場所へ向ける

`packaging_tool/config.py` の既定は**本番の共有フォルダ**です。手元で
試すときは環境変数で向け直します ── **既定を書き換えないでください。**
書き換えるとリリースのときに戻し忘れます。

```bash
PACKAGING_TOOL_MASTER_DB_DIR=/path/to/開発用     # 梱包資材マスタ
PACKAGING_TOOL_LOT_DB_DIR=/path/to/開発用/台帳   # 仕掛台帳
```

設定画面から変えることもできます。その場合の保存先は
`data/user_config.json` で、**このファイルは追跡していません** ──
端末ごとの上書きだからです。追跡していたころは、開発用に向けた
一時パスがそのまま配布物に入り、本番端末が開発用の共有を見に行く
状態でした(書き戻しもそちらへ行きます)。

### 取り込み元(sqlite3)からデータを取り込む

このツールは**手元のDB(`data/packaging_tool.db`)しか見ません**。
共有フォルダに置かれた取り込み元の`.sqlite3`を、使う前に手元へ写します。
普段は**設定画面(`/settings`)の「取り込みと反映」から1回押すだけ**です。
画面を開かずに流したいとき(タスクスケジューラなど)だけ、同じ処理を
コマンドラインから呼べます:

```bash
python3 scripts/import_source.py                # マスタ+仕掛台帳をまとめて
python3 scripts/import_source.py --master-only  # マスタだけ
python3 scripts/import_source.py --lot-only     # 仕掛台帳だけ
python3 scripts/import_source.py --check        # どのファイルが見つかるかだけ表示
```

置き場所は設定画面に保存された値を使います。その場かぎりで別の場所を
指すこともできます:

```bash
python3 scripts/import_source.py /path/to/梱包資材マスタ.sqlite3
python3 scripts/import_source.py --lot-only --lot-dir /path/to/台帳
```

**マスタは3ファイルに分かれています。** 置き場所は設定画面でそれぞれ
指せます(既定はどれも同じフォルダ)。

| ファイル | 取り込むテーブル |
|---|---|
| `梱包資材マスタ.sqlite3` | PalletMaster・BoardMaster・CornerboardMaster・PalletPatterns・梱包保護材・松板角材・資材パレット注文管理・パレット入出庫履歴・**アクセス権限** |
| `看板マスタ.sqlite3` | Form状態管理・看板_*(7テーブル) |
| `PalletThresholdMaster.sqlite3` | PalletDakeThreshold・PalletHabaThreshold・PalletAshiThreshold・PalletKetaThreshold・PalletSymbolMaster・PalletIndustryMaster・PalletComboMaster |

`アクセス権限` が取り込み元に無い端末では、**その端末で足した行だけが
手元に残ります**。モードが切り替えられない・切り替えに開き直しが要る、
という声の出どころはたいていここなので、設定画面の「いまの状態」で
確かめてください。

**パレット閾値マスタが見つからなくても止まりません。** 手元に入れてある
基準表の初期値(`pallet_threshold.SEED`)で動きます ── ただし資材課が
直した値は届いていないので、設定画面がその旨を出します。

**仕掛台帳**(ロット一覧用)は**マスタとは別の3ファイル**を見ます。
`SIKALOT.sqlite3` / `SIKAHIKI.sqlite3` / `SIKAODR.sqlite3`
(いずれもテーブル名は「仕掛」)で、ホスト系から出力される参照専用データです。
VBA版が社内ネットワーク共有 `\\nlmsrvngy03\Read\【New】仕掛\台帳\` の
`.accdb` を ACE OLEDB で直接読んでいたのに対し、Python版は**同じ3ファイルの
sqlite3版**を取り込みます。取り込むのは元のSELECT文が読んでいた列だけです
(`仕掛ロット` 17列 / `仕掛引当` 5列 / `仕掛受注` 13列)。

**日々更新されるデータなので、定期的な再取り込みが必要**です
(再実行すると総入れ替えになります)。未取り込みでも他の機能は動き、
ロット一覧に案内が出るだけです。

実データで確認できた注意点:

- **ロット番号は一意ではありません**。BOX工程(`BOX設計_設備名`・`BOX番号`)
  ごとに行が分かれ、頂いたデータでは2,159行が1,551ロットでした。元のテーブルも
  キー無しのスナップショットで、VBA `SearchLotInfo` は先頭レコードだけを
  見ます。Python版も代理キー(`管理番号`)を立てて取り込み順の先頭を引き、
  ロット一覧も同じ行だけを出します(**一覧と1件検索で結果がずれない**)
- BOX実績系の列は空欄の行が多いので、欠損は列の型に応じた既定値
  (数値0 / 文字列空)で埋めます
- **列名は半角カナ混じり**です(`ﾛｯﾄ番号`・`用途ｺｰﾄﾞ`・`ｵｰﾀﾞｰ板厚`など)。
  元ファイルの列名が違うと取り込みは**黙って空で通ってしまう**ため、
  期待する列が無いときは取り込み結果に理由を出します。ロット番号のような
  鍵の列が無い場合はその表を**取り込みません**(空のまま上書きしない)

## テスト

```bash
python3 -m unittest discover -s tests -t . -v
```

> **`-t .`(トップレベルの指定)を付けてください。** これがあると
> `tests/__init__.py` が読まれ、テスト中のログ・利用者設定・ローカル領域が
> 一時フォルダへ向きます。付けないとテストは**パッケージ配下ではなく単体の
> モジュールとして**取り込まれ、この準備が丸ごと効きません。
>
> 付け忘れても本物を壊さないよう、`tests/_isolation.py` が取り込み時に
> 向き先を見て直し、`tests/test_isolation.py` が直っていることを確かめます
> (`data/user_config.json` は端末ごとの上書きなので**追跡しません**。
> 上の「開発中に取り込み元を別の場所へ向ける」を参照)。
> それでもログは `logs/` に毎回8,000行以上が追記されるので、`-t .` を
> 付けるのが本筋です。

**どこでも全件流せます。** 表示環境は要りません(CI・サーバ・WSLで通ります)。
残るスキップは実データ(取り込み元の`.sqlite3`)を要求する十数件だけです。

```bash
python3 scripts/compare_ui.py          # 選定・配置を41通りのゴールデンと突き合わせ
python3 scripts/check_contrast.py      # 配色のコントラスト比(3テーマ / 387組)
python3 scripts/check_encoding.py      # 文字化けの切り分け(読み方の問題か、元が壊れているか)
```

> **`data/packaging_tool.db` は追跡しません。** 取り込みで作り直せる
> 運用データで、しかも**開くだけで**(`PRAGMA journal_mode=WAL`)中身が
> 変わります。無ければ起動時に `schema.sql` から作られます
> (手で作るなら `python scripts/init_db.py`)。
> 追跡していたころは 2.1MB の実データがリポジトリに入り、アプリを
> 動かすたびに差分が出ていました。

## VBA版との主な違い(Access → SQLite移植にあたって)

- **型**: AccessのYes/No型はSQLiteでは`INTEGER`(0/1)、日付/時刻型は
  ISO8601形式(`YYYY-MM-DD HH:MM:SS`)の`TEXT`として保存します。
  詳細は `packaging_tool/schema.sql` 冒頭のコメントを参照してください。
- **主キー採番**: VBA版は`MAX(管理番号)+1`を手計算しており複数端末同時実行時に
  重複する可能性がありましたが、SQLite版は`INTEGER PRIMARY KEY AUTOINCREMENT`に
  採番を任せることでこの競合をなくしています。
- **SQLインジェクション対策**: VBA版は`BuildSQLLiteral`で値をSQL文字列に
  手動エスケープして埋め込んでいましたが、Python版は`sqlite3`のプレースホルダ
  (`?`)によるパラメータバインドを使うため、その種のエスケープ処理は不要です。
- **同時更新の検知**: VBA版は「更新日時を読み直して比較→別のUPDATE文発行」という
  2段階処理でしたが、Python版は`UPDATE ... WHERE 管理番号=? AND 更新日時=?`の
  比較送信(compare-and-swap)を1文で行うことで同じ安全性を単純に実現しています。
- **保管位置ボタン**: VBA版はExcelフォーム上に配置した物理ボタン(位置コード)に
  依存していましたが、今回のVBAエクスポートにはそのボタン配置情報が
  含まれていなかったため、Python版は`PalletMaster`に実在する位置から
  動的にボタングリッドを生成します。
- **カット前提ボードの二重配置**: VBA版`PlaceBoardsFromList`のカット前提
  ブロックには「何巡目か(`pNum`)」の判定が無く、さらに重なりチェックを
  バイパスして配置していたため、同じボードが1巡目と2巡目でまったく同じ座標に
  2回配置されていました(描画上は重なって見えないものの枚数が倍になります)。
  Python版は1巡目のみに限定して修正しています。
- **倉庫連携の二重確認防止**: VBA版`frmWarehouseOrder`の「確認済みにする」処理は
  SQLのWHERE句で「取消済でないこと」しかチェックしておらず、「既に確認済みか」は
  画面側のキャッシュ値でしか判定していませんでした(他端末が確認した直後に
  自分も確認ボタンを押すと、確認日時が意図せず上書きされる可能性がありました)。
  Python版はWHERE句にも「未確認であること」を追加し、この隙間を塞いでいます。
