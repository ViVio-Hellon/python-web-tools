# 変更履歴

版は `config/app.json` の `version` **ただ1つ**が出どころです。
画面の帯のバッジ・起動待機画面・設定画面・`GET /api/health` は
すべてここを読むので、**上げる場所は1か所**です。

```json
{ "version": "1.0.0" }
```

---

## 版の上げ方

`メジャー.マイナー.パッチ` の3つの数字だけを使います。
判断の基準は「**現場が何をし直すことになるか**」です。

| 桁 | 上げるとき | 現場に起きること |
|---|---|---|
| **メジャー** | 手順が変わる。押す場所・並び・言葉が変わる | 覚え直しが要る。事前に周知する |
| **マイナー** | できることが増える。既存の手順はそのまま | 触らなければ今までどおり |
| **パッチ** | 直しただけ。見た目も手順も変わらない | 何も要らない。黙って入れ替えてよい |

判断に迷ったら**大きいほうへ寄せます。** 「変わらないと思っていたら
変わっていた」は、現場が画面を信用しなくなる出来事だからです。

### 上げるときの手順

1. `config/app.json` の `version` を書き換える
2. このファイルの先頭に、その版で何が変わったかを1節足す
3. 試験を通す(`python3 -m unittest discover -s tests -t . -q`)
   ── 版の書き方は `tests/test_app_config.py` が機械で見ています

配るときは**フォルダごとコピー**します。入れ替えたあとに現場から
「どれが入っているか」と聞かれたら、画面左上のバッジを読んでもらえば
答えられます(`VER2.9.0`)。

> **上げ忘れは機械が見ています。** `tests/test_app_config.py` が
> 「`config/app.json` の版に対応する節がこのファイルにあるか」を確かめる
> ので、版を上げずに配ろうとすると試験が落ちます。逆に、版を上げたら
> ここに1節足すまで試験は通りません。

## VER2.9.0

**看板(在庫薄警告)マスタを、梱包資材マスタとは別ファイルとして
読むようにしました。** あわせて、設定画面に「看板マスタ」の置き場所を
足しています。

### 何が起きていたか

Form状態管理・看板_大板小板・看板_AIM・看板_HVC・看板_LVC・看板_L1・
看板_コイル・看板_LS の8テーブルは、以前は梱包資材マスタ.sqlite3の
一部として取り込む定義になっていました。ところが現場の梱包資材マスタ
には**この8つが一度も入っておらず**、取り込みのたびに

```
11テーブル / 合計12589件を取り込みました。
  (…)
次のテーブルは取り込めませんでした:
  Form状態管理: … no such table: Form状態管理
  看板_大板小板: … no such table: 看板_大板小板
  (以下6件も同じ)
```

という「失敗」に数えられていました。設定画面の「いまの状態」でも
「テーブル 17個(不足 8件)」と出続け、直しようがありませんでした
(取り込み定義を書き換えるしかなく、置き場所を直す画面には手立てが
無かったため)。

現場から渡された実データは**看板マスタ.sqlite3という別ファイル**に
入っていました。

### どうしたか

この8テーブルだけ、梱包資材マスタとは別に**看板マスタ.sqlite3**から
読むようにしました。設定画面の「取り込み元」に3つ目の欄
「看板マスタ」を足しています(既定値は梱包資材マスタと同じ共有
フォルダ。現場の実データがそこに置かれていたため)。

「いまの状態」にも「看板マスタ」の面を新設しました。梱包資材マスタの
面からはこの8テーブルを除外したので、**本来そこには無いものが
「不足」に数えられることは無くなります**。

看板マスタが見つからないときは、8件のエラーではなく案内を1件だけ
出します。アクセス権限(VER2.6.0)と違って機能自体が任意なわけでは
ありませんが、分けたばかりで置き場所が未設定の端末が多いうちは
「毎回失敗」に見せないためです。置き場所を明示して(コマンドラインの
`--kanban-db` 等で)指定したのに開けない場合は、これまでどおり
テーブルごとの詳しいエラーになります。

置き場所を**変える**ときは、梱包資材マスタ・仕掛台帳と同じく管理者
パスワードが要ります(VER2.7.0のガードと同じ理由)。

### 現場に起きること

看板マスタ.sqlite3を「看板マスタ」の欄が指す場所に置くと、この8つも
取り込まれるようになります。置いていない端末は、これまでどおり
現場モードの操作に支障はありません(在庫薄警告を使わないだけです)。

## VER2.8.1

**上用ボードの丈補填で、既存行に足すときだけ枚数が水増しされる不具合を
直しました。** ボード自動選定の内部処理のみで、押す場所も操作も
変わりません。

### 何が起きていたか

上用選定の「丈補填フェーズ」で、丈残を埋める小型ボードを**同じ種類の
既存行へ+1する**とき、丈残の減算量を向き判定(`_orient`)の再計算
結果から取っていました。

丈補填ボードは短辺だけを丈方向に使う配置です。ところが `_orient` は
**幅フィット優先**の向きを返すため、たとえば 30×1600 のボードで
実際に埋まったのは短辺の 30mm だけなのに、長辺の 1600mm を埋めたと
誤認していました(新規に1行追加するときは正しく短辺を使っていたので、
**2回目以降の+1のときだけ**この誤りが起きていました)。

丈残を大きく埋めたと誤認すると、丈補填ループはそこで終わってしまい、
実際にはまだ足りていない丈をそのまま「カバー済み」として扱います。

### あわせて直したもの: 補填の行き先を間違えていた

丈補填の既存行マージが、**タグを問わず同じ寸法の行なら何でも**+1
していました。そのため「幅補填」用に確保してある行(丈カバーには
寄与しない専用枠)に丈補填の枚数が紛れ込むことがあり、実際の丈カバーは
伸びないまま丈残だけ消費した扱いになっていました。

同じ考え方の抜けが、下用の「幅補填行の丈カバレッジ再確認」にも
ありました。丈補填ボード(丈方向の穴埋め専用)を誤って幅方向ストリップ
として丈カバー量の判定にかけてしまい、無関係な枚数を水増しする
ことがありました。

### 現場に起きること

**操作は何も変わりません。** 選定結果の内訳(枚数)が変わることが
あります ── これまで水増しされていた分が正しい枚数に戻ります。

## VER2.8.0

**簡易在庫の「保管位置」でも配置編集ができるようになりました。**
あわせて、**背景の写真に合わせこむための拡大縮小**を両方の図に
入れています。

### ① 簡易在庫の保管位置を、画面から直せます

これまで保管位置の図を直す手立ては画面にありませんでした
(`pallet_map.json` を手で書き換えるしかない)。棚検索の配置図には
配置編集があるのに、こちらだけ無かったのです。

位置が増えたのに図を直せないと、**その棚のパレットは図から押せません**。
図に無い位置の在庫は「図に無い位置に在庫があります」と出るので、
増えたことには気づけます ── 気づけるのに直せない、という
行き止まりでした。

棚検索と**同じ約束**にそろえてあります(覚え直しを増やさないため)。

| | |
|---|---|
| 編集モードの入り切りが要る | 図はよく押す(在庫を見る)ので、常時ドラッグできると見るつもりの操作でずれる |
| 保存するまでファイルに触らない | 間違えて動かしても、開き直せば元に戻る |
| 足す・消す・背景の差し替え | 棚検索と同じ操作 |

### ② 箱の大きさを変えられます(両方の図)

出荷時の大きさは**どれも同じ四角**です。実際の棚は間口も奥行も
まちまちなので、写真を下敷きにすると箱だけが浮きます。

**右下の角を掴んで**大きさを変えられるようにしました。掴んだ角だけが
動き、**左上は動きません** ── どちらが動くのか分からない操作は、
合わせこみの邪魔になります。

小さくしすぎて掴めなくなること、図より大きくして端が見えなくなること、
広げた結果はみ出すことは、いずれもサーバ側で止めます。

### ③ 背景の写真そのものをずらせます(両方の図)

写真の画角は図の枠と一致しないので、**枠いっぱいに引き伸ばすと必ず
ずれます**。これまでは引き伸ばすだけで、位置も倍率も動かせませんでした
(`floor_plan.json` にはもともと項目があったのに、使われていません
でした)。

「背景の合わせこみ」で **倍率・よこ・たて** を入れられます。
**箱は動きません** ── 箱を全部動かして写真に合わせるより、下敷きの
側を合わせるほうが早く、やり直しても箱の位置は壊れません。

掴んで動かす形にはしていません。箱を掴む操作とぶつかって、どちらが
動いたのか分からなくなるからです。数で入れると**同じ量を何度でも**
やり直せます。

### ④ 棚検索にも拡大縮小が付きました

簡易在庫にはあった図の拡大(100% / 150% / 200% / 300%)を、棚検索にも
同じ刻みで入れました。等倍のままだと置き場1つが小さく、**指で狙った
場所へ置けません**。

### ついでに直したもの: 背景の写真が一度も出ていませんでした

合わせこみを作るにあたって図に写真を出したところ、**どちらの画面でも
出ませんでした**。原因は2つあり、どちらも別のものです。

**簡易在庫** … 背景を `background.path` から読もうとしていました。
その項目はありません(あるのは `image`)ので、背景を設定しても必ず
「設定されていません」になっていました。棚検索は最初から `image` を
見ていたので、こちらだけの取り違えです。

**両方** … 図の中の `<image>` は**ヘッダを付けられない読み込み**なので、
起動トークンが載らず 401 で弾かれていました。同じ用途の
`tokenUrl()`(印刷やロットの写真が使っている)を通すようにしました。

### 現場に起きること

**今までの操作は変わりません。** 「配置編集」を押さないかぎり、
図はこれまでどおり押して在庫を見るだけです。

## VER2.7.0

**取り込み元の置き場所を変えるとき、管理者パスワードが要るように
しました。** 変えないで保存するときは今までどおりです。

### なぜ置き場所だけなのか

置き場所を変えると、**このツールが読み書きする相手そのもの**が
変わります。取り込みは総入れ替えなので、間違った先を指したまま
取り込むと手元の中身が入れ替わり、書き戻しもそちらへ行きます。

押し間違いが**別のファイルを書き換える**ところまで届く設定は、
いまここだけです。自動取り込み・拠点・仕様書URL・よく使う条件は、
間違えてもその端末の見え方が変わるだけなので守りません。

> **守る対象を増やすほど、現場はパスワードを紙に貼ります。**
> 増やすときは「押し間違いがどこまで届くか」で決めてください。

### 変えるときだけ聞きます

設定画面は置き場所を毎回まとめて送ります。値が変わらない保存まで
聞くと「何をしても聞かれる」になり、パスワードそのものが形骸化
するので、**いま入っている値と違うときだけ**聞きます。

空にして既定へ戻すのも「変えること」なので聞きます。

パスワードの欄は、押す前には出しません。**断られてから開きます**
── 変えない人にまで打たせないためです。

### これは権限ではありません

誤って押されないためのUIガードです。誰がその端末を使えるかは
`アクセス権限` マスタが決めます(VER2.6.0)。パスワードは
設定画面の「管理者パスワード」で変えられ、平文では持ちません。

### 断りの種別

置き場所の断りは **403**(許されていない)で返します。
入力の形の誤り(**400**)とは別のものとして扱うので、画面は
文言から推し量らずに、パスワードの欄を出すかどうかを決められます。

### 現場に起きること

置き場所を変える機会はほとんどありません。変えるときだけ、
保存を押したあとにパスワードの欄が出ます。

### ついでに直したもの: 隠したはずのものが出ていた

パスワードの欄が**最初から見えていた**ので調べたところ、
`hidden` を付けても隠れない箇所が他にもありました。

ブラウザ内蔵の「隠す」指定(`display:none`)は、こちらが書いた
`display:flex` などより**弱い**ためです。しかも隠れないだけで
壊れたようには見えないので、書き忘れても気づけません。

実際に出ていたもの:

| どこ | 何が |
|---|---|
| 設定 → マスタ管理 | 表の札(`.st`) |
| ロット検索 | よく使う条件の帯 / 「ありません」/ 仕様書の欄 |
| 設定 → 取り込み元 | 管理者パスワードの欄 |

class ごとに書き足すのをやめ、**土台で1回だけ**決めました。
全画面で確かめて、隠れないものは0件です。

## VER2.6.0

**アクセス権限マスタを、画面から作れるようにしました。**
これが無いあいだは**どの端末も現場モードだけ**になります。
「モードが切り替わらない」の原因が、ここでした。

### 何が起きていたか

アクセス権限はこのツールが後から足した表で、**既存の梱包資材マスタ
には入っていません**。無くても取り込みは失敗しません(無いことを
失敗と数えると、取り込みが毎回「失敗」と出て本当の問題が埋もれる)。

そのぶん、無いことがどこにも現れませんでした。

```
アクセス権限が無い
  → どの端末も現場モードだけ(締め出さないための既定)
  → 帯のモード切替に選択肢が1つしか出ない
  → 「切り替えが効かない」としか見えない
```

しかも直しようがありません。マスタ管理の一覧は**取り込み元にある表
だけ**を並べていたので、アクセス権限は画面のどこにも出ませんでした。
最初の1行を入れる場所が無い、という行き止まりです。

### どうしたか

**無い表も一覧に出します。**「まだありません」の札と、それが何を
意味するか(現場モードだけになること)を添えます。
「+ 取り込み元に作る」を押すと、取り込み元に空の表ができます。
あとは普段どおり「+ 行を足す」で登録します。

```
ログインID  PC名        権限            有効
(空)        NLM-PC-042  mode:material   1     … この端末は誰でも資材
yamada      (空)        mode:material   1     … 山田はどのPCでも資材
suzuki      NLM-PC-042  mode:material   1     … 鈴木がこの端末のときだけ
```

空欄は「問わない」です。**両方が空の行は効きません** ── それは
全員への許可で、権限を設ける意味が消えるからです。

### 作るのは、このツールが足した表だけ

PalletMaster のような上流の表は作りません。無いのは資材課側の事情
(ファイルが違う・移された)で、空の表を作ってしまうと**その事情が
「0件」という形に化けて**、原因を探せなくなります。

判断の出どころは取り込み定義の `OPTIONAL_TABLES`(取り込み元に
無くても失敗にしない表)で、別の一覧は作っていません。

### 最初の1行は、権限が無くても入れられます

ここを資材モードで塞ぐと、資材モードに入るための最初の1行を
どこからも入れられなくなります。**登録が1行でもあれば、その時点で
閉まります**(従来どおりの動き)。

### 現場に起きること

**今までの操作は変わりません。** アクセス権限を登録していない端末は
これまでどおり現場モードだけで動きます。登録すると、帯のモード切替に
資材モードが出ます(全部が効くのは開き直してからです)。

## VER2.5.4

**適合範囲の基準表を、Access側の更新に合わせました。**
幅の帯が広すぎて「そのパレットには載らない製品まで適合」に
なっていたのを直し、基準表に無い大きいサイズも現物に合わせて
延長しました。

### 何が変わったか

**1. 幅の帯を全域50mm刻みにしました**

1050より上だけが100mm刻みのまま残っていて、帯が倍の幅を
持っていました。

```
幅1100のパレット … 帯「1051〜1150」→ 下限1041
幅1050のパレット … 帯「1051〜1150」の1つ下 → 下限991
```

1100幅と1050幅が同じ帯を分け合うので、**1100幅のパレットが
1050幅相当の小さい製品まで適合**と名乗っていました。
1100 / 1200 / 1400 / 1500 / 1600 / 1700 / 1800 / 1900 / 2000 の
区切りを補い、全域を `帯の下限 - 10` にそろえてあります。

**2. 基準表に無い範囲を現物に合わせて延長しました**

操業基準表は丈6100 / 幅1850までしかありません。それを超える
現物があるので、同じ刻みで延長しました。

| 方向 | これまで | これから |
|---|---|---|
| 丈 | 6100超はすべて頭打ち | 6600 / 7100 まで2段。7100超が頭打ち |
| 幅 | 1850超はすべて頭打ち | 2050 まで。2050超が頭打ち |

### 現場に起きること

**操作は何も変わりません。** マスタ管理の「適合範囲を再計算」を
押した後の値が変わります。**押すまでは今までの値のまま**なので、
入れ替えただけでは選定結果は動きません。

### 変えていないもの

桁数・脚数の段階表、記号別(C1〜C8 / P1〜P7)と業界別の固定適合表、
複合キー(`5×10|強度UP`)は移植元と同じで、今回は触っていません。
現物サイズでの頭打ち(`適合max = 現物 - 10`)もそのままです。

## VER2.5.3

**書き方が少し違うだけで固定適合を取りこぼしていたのを直しました。**
拾ったことは**黙らずに知らせます**。

### 何が起きていたか

移植元の `NormalizeKey` は `Select Case` の評価順の都合で、
半角小文字 `x` と全角 `Ｘ`/`ｘ` が「×」ではなく半角大文字 `X` に
なっていました。そのため

```
業界「5X10」 → 5×10  … 固定表に当たる
業界「5x10」 → 5X10  … 当たらない(段階表からの計算に落ちる)
```

と、**同じ寸法の書き方で結果が割れて**いました。

### そろえる4つ

1. 前後と**中の空白**を詰める(「5 × 10」も同じ鍵)
2. 全角の英数字を半角に、英字を大文字に
3. かけるとしか読めない記号(`×` `✕` `✖` `╳`)は `×` に
4. **数字に挟まれた** `X` `x` `Ｘ` `ｘ` `*` `＊` だけを `×` に

**4 で位置を見るのが要点です。** 挟まれていないものまで変えると、
`EXﾀｲﾄ`(実マスタに74行)が `E×ﾀｲﾄ` に、`EX2方向`(26行)が
`E×2方向` になります ── そこの X は EX受注 の X で「かける」では
ありません。固定表の鍵は `1×2` `4×8` `5×10` `4×10` `3×6` `5×8` と
**すべて数字に挟まれた形**なので、この規則で取りこぼしは出ません。

### 拾ったことを知らせます

そろえて初めて当たった行は、**管理番号と元の文字**を並べて出します。
選定は通りますが、マスタにゆれが残っていること自体は直したほうが
よい事実なので、両方を言います。

```
書き方をそろえて拾った行: 3件
```

## VER2.5.2

**パレットの「適合範囲を再計算」を、移植元と突き合わせて直しました。**

数値の表(丈適合min/max・巾適合min/max・脚数)は移植元と**1件も
違いがありません**でしたが、3か所が食い違っていました。

### ① 桁数が、幅1801以上で1本少なかった

基準表に無い範囲ですが、現物の1900幅パレットの桁が7本だったことから
**7本**が正です。これまでは6本で止めていました。

| 幅 | これまで | いま |
|---|---|---|
| 〜1800 | 6 | 6 |
| 1801〜 | **6** | **7** |

手元のマスタでは 2,586行中 **104行**がこの範囲に入ります。ただし
桁数はもともと**取り込み元の値がそのまま入る**ので、実際に効くのは
取り込み元が空だった行(下の②③)です ── 取り込み元に値があれば、
これまでどおりそちらが優先されます。

### ② 脚数・桁数が、手で入れた値を上書きしていた

移植元は**空のときだけ埋めます**(補完)。現場が手で入れた本数を
潰さないためです。これまでは計算で埋めた行で毎回上書きしていました
── 手元のマスタでは **2,532行**が毎回上書きされていました。

空とみなすのは **未入力・空文字・0** の3つです(取り込み元の欄が0で
埋まっていることがあり、空欄と意味は同じ)。

> **桁数・脚数の出どころは取り込み元です。** 取り込みは総入れ替えなので、
> 取り込み元に値があればそれが入り、再計算は**空いているところだけ**を
> 埋めます。値そのものを直したいときは、取り込み元(またはマスタ管理)で
> 直してください。

### ③ 業界だけで当たった行に、脚数・桁数が入らなかった

移植元では、範囲を固定表から入れた行も計算した行も、最後は必ず同じ
後始末を通ります。これまでは記号で当たった行だけしか通っていなかった
ので、**1×2 / 4×8 / 5×10 などの行は脚数・桁数が空のまま**でした。

いまの通り道は移植元と同じです。

```
範囲を決める(複合キー → 記号 → 業界 → 計算)
        ↓ どの道を通っても
脚数・桁数を、空なら埋める
```

記号で当たった行だけは、表の値で**上書き**します(記号は現物の型
そのものなので、表のほうが確かな事実)。

### 何件直ったかが出るようになりました

「終わりました」だけでは、直ったのか何も起きなかったのかが

**取り込み元から来た行を新しい行としてもう一度**送っていました。
送信IDは送るたびに振り直されるため、一意索引の重複防止も効きません。

- 取り込んだ直後に、そのテーブルの行を**送信済みとして記録し直す**
  ようにしました。取り込んだ行は取り込み元から来たものなので、
  送り返す必要がありません
- 古い記録は消します。番号が振り直されたあとの古い行IDは**別の行**を
  指すので、残すと今度は**新しく登録した発注が「送信済み」に化けて
  二度と送られなくなります**(こちらのほうが気づけません)
- **こちらで出した発注はちゃんと送られます。** 増やさないために
  送らなくなる、では意味がありません(試験で固定しました)

### すでに増えてしまった行の片付け方

**順番が大事です。** 増えた行は取り込み元だけでなく、**各端末の手元にも
写っています**。入れ替えた直後の1回目の取り込みで、その手元の分が
取り込み元へもう一度送られます(そこで止まります)。なので、
**全部の端末が1回ずつ取り込んでから**片付けます。

1. **全端末を入れ替える。** 古い版が1台でも動いていると、また増えます
2. **各端末で1回ずつ取り込む**(起動すれば自動で走ります)。
   ここで最後の1回ぶんが送られ、以後は増えません
3. **数える。** どこか1台から。数えるだけなら安全です

   ```bat
   python scripts\dedupe_writeback.py
   ```
   ```
   対象: \\…\梱包資材マスタ.sqlite3
     資材パレット注文管理: 64件 → 重複 62件
     パレット入出庫履歴: 12件 → 重複なし
   ```

4. **消す。** `--fix` を付けます。**消す前に、同じフォルダへ丸ごと控えを
   取ります**(`梱包資材マスタ.bak-20260809103000.sqlite3`)。
   管理番号と送信IDを除いた全部の列が一致する行を重複とみなし、
   **いちばん小さい管理番号だけを残します**

   ```bat
   python scripts\dedupe_writeback.py --fix
   ```

5. **もう一度、各端末で取り込む。** 手元を、片付けたあとの取り込み元に
   合わせます

> 手順2を飛ばして先に消すと、手元に残っていた分が次の取り込みで
> また送られ、消したはずの行が戻ります。

## VER2.2.0

**共有フォルダのマスタが「sqlite3 として読めません」になるのを直しました。**
既存の手順は変わりません。

仕掛台帳(SIKA*)は読めるのにマスタだけ読めない、という形で出ていました。
同じフォルダ・同じ経路なので、違いは**そのファイルがどう作られたか**
だけです。原因は2つ重なっていました。

1. **開けたかどうかを確かめていませんでした。**
   `sqlite3.connect()` はファイルを触りません。開けたつもりのまま
   返ってきて、最初の問い合わせで初めて落ちます。そのため
   「別の開き方を試す」逃げ道が**一度も動いていませんでした**
2. **落ちた理由を捨てていました。** 画面には
   「sqlite3 として読めません」としか出ず、**なぜかが分かりません**

直したこと:

- 開くところで1文引いて、**引けたら開けた**と決めるようにしました。
  これで手を変えられます ── `URI(読み取り専用)` →
  `素のパス` → `手元への写し` の順に試します
- **共有の上で開けないときは、手元へ写してから読みます。**
  WAL で作られた sqlite3 は共有フォルダの上では開けません(共有メモリが
  要るため)。写せば読めるので、読むたびに写します。`-wal` / `-shm` も
  一緒に写すので、直前に書かれた分が抜けることもありません
  (書き戻しは写しへ逃がしません。書いたものがどこにも残らないため)
- **開けなかったときは、分かったことを全部出します。**
  大きさ・先頭の印・付き添いファイル・試した順と、それぞれの理由。
  そして次にすること(「変換したPCで `PRAGMA journal_mode=DELETE;` を
  実行して置き直してください」など)
- ふだんの開き方で通らなかったときは、動いていても「開き方」の行が
  出ます ── 写しながら動いているのは遅いので、黙っていません

**置き場所の指定が2通りになりました。**

| 書き方 | 例 | どこを見るか |
|---|---|---|
| 絶対 | `\\サーバ\共有\…` / `C:\data\…` | そのまま |
| 相対 | `data\src` / `..\共有` | **アプリのフォルダ**から |

相対の起点を「いまの作業フォルダ」にしないのが要点です。作業フォルダは
どこから起動したかで変わるので、同じ設定でも端末ごとに違う場所を
指すことになります。アプリのフォルダなら、**フォルダごとコピーして
配る運用でも写しの中の同じ場所**を指し続けます。
相対で書くと、その下に**実際の行き先**が出ます。

- 「参照…」で**ファイルを押しても選べる**ようになりました。目当ての
  ファイルが見えているのに「フォルダを選べ」と言われるのは一手多い
  ── 押すとその入れ物が入り、押したファイルに印が付きます
- 「参照…」の欄は相対でも開けます(どこから見た相対かは1か所で
  決まっているので、断る理由がありません)

## VER2.1.0

**梱包資材マスタを画面から確認・修正できるようになりました。**
既存の手順は変わりません。触らなければ今までどおりです。

マスタはこれまで起動のたびに**黙って読まれるだけ**で、中に何が入って
いるかを見る手立ても、間違いを直す手立ても画面にありませんでした。
値が違っていても、現場には「パレットが出ない」「ボードの候補が
足りない」という形でしか現れず、原因に辿り着けませんでした。

設定画面に「**マスタ管理**」の面を足しました。

- **確認はどの表でもできます。** 取り込み元にある表を全部並べ、
  行数も出します。行を押すと1行ぶんが縦に並ぶので、18列ある表も読めます
- **絞り込みはどの列でも当たります。** どの列に何が入っているかを
  覚えていなくても引けます
- **直せるのは資材課の6表**です ── パレット / ボード / アングル /
  梱包保護材 / 松板・角材 / アクセス権限。残りは見るだけで、
  **なぜ直せないのかもその場に出ます**(実績から貯まる表・このツールが
  書き戻す表・上流の設備が書く表)

**直す先は取り込み元(共有フォルダの sqlite3)です。** 手元の写しは
取り込みのたびに総入れ替えされるので、手元を直しても次の取り込みで
消えます。元を直したあとは、その表だけをその場で取り込み直すので、
**直した結果はすぐ画面の動きに効きます**(パレットなら適合範囲も
計算し直します)。他の端末にも、次の取り込みで届きます。

**直せるのは資材モードを持つ端末だけです。** 現場モードの端末では
見るだけになり、「なぜ直せないのか」と「何をどこに足せばよいか」が
画面に出ます。まだ誰もアクセス権限マスタに登録されていないあいだは
塞ぎません ── そうしないと、最初の1行をどこからも入れられません。

> **登録を1行入れると、その時点で関門が閉まります。** 条件(ログインID /
> PC名)を書き忘れた行を入れると、その行は誰にも効かないので全員が
> 現場モードに落ち、画面からは直せなくなります。そうなったときは
> 取り込み元の sqlite3 を直接開いて直してください(この面ができる前と
> 同じ手順です)。書き忘れた行は「いまの状態」の面が警告に出します。

その他:

- 隠したはずのボタンが押せる場所に残ることがあったのを直しました
  (`display:inline-flex` が `hidden` より強かった)

## VER2.0.1

**共有フォルダ(UNC)の取り込み元が1件も読めなかったのを直しました。**
入れ替えるだけで直ります。手順も見た目も変わりません。

現場ではマスタも仕掛台帳も、全部のテーブルがこう出ていました:

```
BoardMaster: 梱包資材マスタ.sqlite3 を開けませんでした:
invalid uri authority: nlmsrvngy03
```

ファイルは正しく sqlite3 になっていて、共有にも届いていました。
折れていたのは**開くときの道の書き方**です。`\\サーバ\共有\…` を
標準の変換に掛けると `file://サーバ/共有/…` になり、SQLite はこの
`//サーバ` を接続先(authority)として読みます。SQLite が受け付ける
authority は空か `localhost` だけなので、サーバ名を書いた時点で
断られていました。取り込み元は**全部**共有フォルダに置くので、
これに当たると1件も読めません。

- サーバ名は接続先ではなく**道の一部**として書くようにしました
  (`file:////サーバ/共有/…`)。指すファイルは同じです
- それでも開けない端末のために、素の道でもう一度だけ試します。
  そのときも**読み取り専用は必ず掛けます**(取り込み元へは書きません)
- ついでに、道を絶対形にするのに**共有へ問い合わせなくなりました**。
  以前はテーブル1つごとに共有へ往復していたので、取り込みが少し速くなります
- 同じ折れ方を二度としないよう、実際に出たパス3本を試験に入れました
  (`tests/test_source_db.py`)

## VER2.0.0

**資材選択の手順が変わりました。事前に周知してください。**

決まっていく順は「ロットを選ぶ → 製品サイズが入る → それが載る
パレットが決まる」です。パレットは製品のために選ぶもので、
画面もその順に直しました。以前は パレット → 製品 の順に2枚のカードが
並んでいて、**まだ分からないものを先に決めさせ**、あとから
「載るかどうか」を確かめる形になっていました。

| | 以前 | いま |
|---|---|---|
| 押す回数 | 3回(行を選ぶ → 適用 → セット) | **1回** |
| 順番 | 間違えると断られる(セットはパレットの後) | 順番は無い |
| 候補の一覧 | 別のカードにあり、畳まれていることがある | 同じカードの中に見えている |

- 「製品サイズ」と「パレットサイズ」の2枚を**1枚**にまとめ、
  題を「**パレットを決める**」にしました
- 「パレット検索」と「セット」は「**パレットを選ぶ**」1つになりました。
  載るパレットを探し、載ることを確かめ、両方を確定するところまで
  1回で行います
- **一覧の行を押した時点で決まります**(適用もセットも要りません)
- 一覧に無い寸法を使う道は残してあります(「一覧に無い寸法を使う」を開く)

**確かめる規則は1つも変えていません。** 載らないパレットを選べば
今までどおり断られます(`apply_product_size`)。押す回数を減らしただけです。

その他:

- 利用者設定(`data/user_config.json`)を追跡対象から外しました。
  端末ごとの上書きで、追跡していると**開発用に向けた一時パスが
  配布物に入ります**。取り込み元の既定は `packaging_tool/config.py`
  にある本番の共有フォルダです
