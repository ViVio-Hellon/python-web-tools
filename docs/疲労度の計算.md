# 疲労度の計算

疲労度は「その資材を使うと、現場の人がどれだけ疲れるか」を点数にしたものです。
**点が小さいほど楽**です。次の3か所で同じ式を使います。

| どこで | 何に使う | 入れる項 |
|---|---|---|
| ボード選定(疲労度優先がON) | 候補のボードを比べて、点の小さいほうを選ぶ | 運搬・枚数・カット |
| アングル自動選定(疲労度優先がON) | 1本で使う・1本を切る・2本で使う を比べる | 運搬・本数・カット |
| 棚検索の「置き場をまとめて見る」 | 選んだ資材を全部取ってくる **合計疲労度** を出す | 運搬・枚数(カットは入れない) |

疲労度優先がOFFのときは、ボード選定もアングル選定も疲労度を見ません(幅の近さなど、いつもの順番で選びます)。

---

## 1. 式

```
総疲労 = 距離 × 1            … 棚まで歩く(何枚取っても1往復)
       + 面積 × 枚数          … 運ぶ(大きい板ほど重い)
       + 手間 × 枚数          … 1枚ずつの取り回し・テープ貼り
       + 幅カット × 枚数      … 幅を切るなら全部の板を切る
       + 丈カット × 1         … 丈がはみ出すなら最後の1枚だけ切る
```

アングルは「面積」の代わりに「長さ」、「枚数」の代わりに「本数」です。

### 1つずつの点

| 項 | 計算 | 上限 | 例 |
|---|---|---|---|
| 距離 | 拠点から最寄りの置き場まで(配置図の上の距離) ÷ 1000 × 50 | 50 | 距離100 → 5点 / 距離1000 → 50点 |
| 面積(1枚) | 幅 × 丈 ÷ (3000 × 3000) × 50 | 50 | 1100×2000 → 12.2点 / 400×1100 → 2.4点 |
| 長さ(アングル1本) | 丈 ÷ 3000 × 50 | 50 | 2500 → 41.7点 / 1300 → 21.7点 |
| 手間(1枚・1本) | 決まった値 | ― | **5点(仮の値)** |
| カット(1回) | 切断線の長さ ÷ 3000 × 233 | 233 | 切断線1000 → 77.7点 / 1100 → 85.4点 |
| アングルのカット | 1回切ると、配置図の端から端まで歩くのと同じ | ― | **50点**(VER4.8.65。以前は断面50mmを切断線として3.9点) |

- **距離の単位は配置図の上の点です(mmではありません)**。配置図の横幅がおよそ1000です。拠点は設定画面の「動作」で選びます。拠点が変わると距離が全部変わります。
- **カットは重く数えます。** 切断線1000mmのカット1回(77.7点)は、配置図の端から端まで歩く(50点)より重い点です。現場ルールの「カットするくらいなら遠くから運ぶ」は、この重さで効きます。
  ボードは切断線が644mmより短いと50点を下回ります(遠くまで歩くほうが重いことがある)。アングルは1回50点です。
- **疲労度優先は、できあがった選定を数えて比べます**(VER4.8.65。下の「6」)。
- 決め打ちの値は `docs/決め打ちの値一覧.md` の「疲労度」にあります。値の置き場所は `packaging_tool/angle_service.py` の1か所だけです。

## 2. 考え方

### 運搬 ── 距離は1往復、面積は枚数ぶん

同じ置き場の板は、何枚あっても1回で取りに行きます。だから**距離は1回だけ**数えます。
運ぶ重さは板1枚ずつにかかるので、**面積は枚数ぶん**数えます。

棚検索の合計疲労度では、**同じ置き場へ歩くのは1回**として数えます。アングルの2本対称、上用と下用が同じサイズの場合、同じ棚にある別サイズの場合がそれにあたります。

### 枚数 ── 選定が実際に採る枚数で数える

比べるときに掛ける枚数は、**選定がその板を実際に採る枚数**です。

| 選定のどこ | 掛ける枚数 |
|---|---|
| 1枚物(製品を1枚で覆う) | 1 |
| PASS1(パレット幅ぴったり) | パレット丈 ÷ 有効丈(切り捨て) |
| カット前提(幅広を切って使う) | 製品丈 ÷ 短辺(切り上げ) |
| 候補の並べ替え(順番の目安) | 基準丈 ÷ 有効丈(切り上げ)── 基準丈を覆いきる枚数。**手間は入れない**(下の注) |

**手間(1枚5点)を足した理由**: 面積だけで数えると、面積が同じなら「小さい板6枚」と「大きい板2枚」が同じ点になります。取り回しやテープ貼りは枚数に比例するので、1枚ごとに点を足しました。

> 例: 400×1100 を6枚 と 1100×1200 を2枚(どちらも面積の合計は同じ)
> 運ぶ点: 6枚 = (2.4 + 5) × 6 = 44.7点 ／ 2枚 = (7.3 + 5) × 2 = 24.7点

**5点は仮の値です。** 中くらいの板(1100×2000 の面積 12.2点)の4割くらいに置きました。現場の感覚に合わなければ、`angle_service.FAT_SHEET_SCORE` の1か所を直せば全部に効きます。

> **候補の並べ替えには手間を入れません。** 並べ替えは「幅の合い方」に疲労度を割合で掛けて順番を決める作りです。
> どの候補にも同じくらいの手間を足すと疲労度の差が薄まり、幅の合い方だけで順番が決まってしまいます
> (実データで確かめました: パレット 1100×1800 で、1000×1000 ×2枚 が 1030×1520 + 補填3枚 に変わった)。
> 手間は、決めるところ(1枚物・PASS1・カット前提・補填・アングル・棚検索)で足します。

### カット ── 幅は実際に切るときだけ、丈は覆いきる見込み

疲労度は選定の**前**に「この板を使うと切ることになるか」を見積もります。

- **幅カット**は、実際の選定・配置・切断依頼が切るときだけ数えます。
- **丈カット**は「基準丈を覆いきるなら、最後の1枚を切ることになる」という見込みです。実際の選定は、端数を補填板で埋めることもあります。
  それでもこの見込みを残しているのは、**補填板の枚数・運搬が疲労度に入っていない**からです。この見込みが「端数を埋める手間」の代わりになっています。
  外すと、補填が要る板ほど安く見えてしまいます(実データで確かめました: パレット 900×1800 で、900×900 ×2枚 より 750×1130 + 補填3枚 を選ぶようになった)。
- ただし**1枚物**(製品を1枚で覆う板)は端数を埋めないので、丈カットの見込みを数えません。

| カット | 数えるとき | 切断線 |
|---|---|---|
| 幅カット | 有効幅が**切らずに使える幅**を超えるとき。下用 = パレット幅 × 1.2 まで、上用 = 製品幅まで(選定・配置と同じ許容) | 有効丈(1枚ごと) |
| 丈カット | 基準丈を有効丈で**割り切れず端数が出る**とき(最後の1枚を切って覆いきる見込み)。基準丈は 下用 = パレット丈 / 上用 = 製品丈。**1枚物は数えない**(製品を1枚で覆い、端数を埋めないので) | 有効幅(1回) |
| カット前提の幅カット | いつも(全部の板を切る前提) | 短辺(1枚ごと) |
| カット前提の丈カット | 短辺 × 枚数 が基準丈 + 3mm を超えるとき | 対象幅(1回) |
| アングル | 1本カット(製品丈 < 2500mm で、長い1本を製品丈に切る) | 断面50mm(1回) |

## 3. 例(VER4.8.61 で直したところ)

点検で見つけた食い違いです。どれも、直す前のプログラムを実際に動かして確かめました。直したあとの動きは `tests/test_fatigue_fixes.py` が同じ例で確かめています。

### アングル: 1本で製品丈を覆う

製品丈 2400 / パレット丈 2600 / 候補 2500・1300(同じ棚、距離100)

| | 直す前 | 直したあと |
|---|---|---|
| 「1本そのまま」の条件 | 丈 × 2 ≧ 製品丈(半分で通る) | **丈 ≧ 製品丈** |
| 選ばれたもの | 1300 × 1本(**1100mm 足りない**) | 2500 × 1本 |

### アングル: 長さを本数ぶんだけ数える

| 案 | 直す前の点 | 直したあとの点 |
|---|---|---|
| 2500 × 1本 | 88.3 | 5 + (41.7 + 5) × 1 = **51.7**(勝ち) |
| 1300 × 2本 | 70.0(勝ち) | 5 + (21.7 + 5) × 2 = 58.3 |

直す前は、棚ごとの点に「距離 + 長さ1本分」が入っていて、さらに「長さ × 本数」を足していたので、長さが本数+1回入っていました。

### ボード下用: 切らないはみ出し

パレット 1100×2000 / 製品 1000×1950 / 候補 1105×1000(距離100)・1095×1000(距離1000)

1105 はパレット幅を5mm超えますが、下用は切らずに使います(切断依頼にも出ません)。

| | 直す前 | 直したあと |
|---|---|---|
| 1105 の幅カット | 77.7 × 2枚 = 155.4点 | 0 |
| 疲労度ONで選ばれるもの | 遠い 1095 | **近い 1105** |

### ボード下用: 1枚物の丈カット

パレット 1100×2100 / 製品 1050×1950 / 候補 1100×2000(距離100)・1100×2100(距離1000)

1100×2000 は1枚で製品を覆い、パレット丈に収まるので切りません。

| | 直す前 | 直したあと |
|---|---|---|
| 1100×2000 の丈カット | 85.4点(2100÷2000 が割り切れないため) | 0(1枚物は数えない) |
| 疲労度ONで選ばれるもの | 遠い 2100 | **近い 2000** |

### カット前提: 最後の1枚の丈カット

カット前提は枚数を切り上げで決めるので、最後の1枚がはみ出して切ります(切断依頼にも出ます)。直す前はこの1回が点に入っていませんでした。

### 棚検索: 同じ置き場は1往復

| | 直す前 | 直したあと |
|---|---|---|
| アングル 1300 × 2本(距離100) | 5 + 21.7 + 5 + 21.7 = 53.3(距離2回) | 5 + (21.7 + 5) × 2 = 58.3(距離1回、手間を足した) |
| 上用・下用 1100×2000 各2枚(距離100) | 距離を2回 | 距離1回 + (12.2 + 5) × 4 |

### 実データでの影響(疲労度ONのとき)

共有の梱包資材マスタの写し(ハードボード36種・アングル14種、拠点 L1)で、直す前と直したあとを比べました。

| | 比べた数 | 選定が変わった | 中身 |
|---|---|---|---|
| ボード(パレット幅 900〜1650 × 丈 1500〜3100、製品は −20 / −60〜80) | 544 | 75 | 板の枚数(上用・下用の合計)は 5582 → 5387 枚。減った 55 件・増えた 10 件 |
| アングル(製品丈 800〜6000) | 159 | 86 | 直す前は86件とも**製品丈に足りない1本**を選んでいた → 0件に |

- 枚数が増えた10件は、直す前は板がパレット丈を超えて**丈カットが要る**選定でした。直したあとは補填板で埋めて切らない選定です(「カットするくらいなら運ぶ」)。
- 手間を足さずに直すと、ボードの選定が変わったのは10件で、枚数は変わりませんでした。変わった件数の多くは手間を足したことによるものです。
- 疲労度OFFの選定は変わりません。

## 4. 疲労度ON/OFF・拠点(ライン)を替えたとき(VER4.8.62)

| 場面 | どうなるか |
|---|---|
| 疲労度OFF | ボード選定もアングル選定も疲労度を見ない(いつもの順番) |
| 疲労度ONで、棚のデータが引けない | **本当に通常選定で走らせる**。以前は「通常選定で実行しました」と言いながら疲労度モードの経路を点0で走らせていて、実データで544通り中18通りが通常と違った |
| 拠点が配置図に無い(配置編集で消した等) | 距離が測れないので**通常選定に倒して、そう言う**(棚検索は前から断っていた) |
| 置き場が未登録の板 | 距離はアングルと同じ既定の25点。以前はボードだけ0点(いちばん近い扱い)で、未登録の板ほど選ばれやすかった |
| 選んだあとに疲労度を切り替えた | 出ているボードは選び直さない(VBAも同じ)。設定と食い違うときは選定ログに「疲労度ONで選んだもの」と出す |
| 棚検索で拠点を替えた | 出していたものを**新しい拠点から出し直す**(1件の検索も、「置き場をまとめて見る」も)。以前は「まとめて見る」の合計疲労度が前の拠点のまま残っていた |
| 棚検索の「置き場をまとめて見る」 | **選定と同じボード種別の置き場**で距離を測る。以前は種別を見ず、同じ寸法の別種別(プロテックボードなど)の棚が近いとそちらで測っていた |

拠点は設定画面の「動作」で選び、資材選択と棚検索で同じ値を使います。
拠点はマスタでも足せます(BoardMaster のデータラベルに「拠点大板」のように書く。VER4.8.63〜)。足した拠点は棚検索の「配置編集」で図に置くまで距離を測れないので、選んでいても通常選定に倒します。

## 5. 確かめられていないこと

- **VBAの原本はリポジトリにありません。** 直したところがVBAでも同じだったのか、移植のときに入ったのかは確かめられていません。アングルの「1本そのまま」の条件は、最初の移植(VER3.5.15)から変わっていませんでした。
- **手間の5点は仮の値です。** 現場で使ってみて、「小さい板を何枚も選ぶ」「遠くても大きい板を選ぶ」のどちらかに寄りすぎるようなら直します。
- **補填板(幅補填・丈補填)の枚数と運搬は、選定の途中で候補を比べるときの点には入っていません**(主ボードを決めたあとに選ぶため)。
  そのかわり、**できあがった選定どうしを比べるときは補填板も1枚ずつ数えます**(「6」)。疲労度の選定が通常の選定より疲れるなら、通常の選定を採ります。
- 候補の並べ替え(順番の目安)は、基準丈を覆いきる枚数(切り上げ)で数えます。決めるところ(1枚物・PASS1・カット前提)は実際に採る枚数で比べます。

## 6. カットするぐらいなら運搬する ── できあがった選定で比べる・カットは最終手段(VER4.8.65〜)

現場の声:「運搬疲労、カット疲労。カットするぐらいなら運搬するという現場の思想は生きていますか？」

**点検したら、疲労度ONのほうが切る選定が多くなっていました。** 選定の**前の見込み**で比べていたためです。

| 見込みで見落としていたこと | 例 |
|---|---|
| 丈の見込みは「切る」と「補填板で埋める」を見分けられない(どちらも丈カット1回) | 製品 980×1480: 945×2000 を1枚(520mm切る)が、950×950 を2枚(切らない)と同じに見え、1枚で済む切るほうを選んだ |
| 下用(疲労度ONのときだけ)は、点を数えたあとで主ボードを1枚足す(丈残300mm以上) | パレット 950×2600: 945×2000 を2枚にして 1400mm 切る。足した1枚とカットは点に入っていない |
| 上用の並べ替えは、幅が足りずカット前提(全数カット)になることを見込めない | 420×1250 を4枚、全部切る |

**直し方**: 疲労度ONのときは、**通常の選定と疲労度の選定を両方作り、できあがった選定を数えて比べます**。

**カットは最終手段です**(VER4.8.66。現場の声:「カットは絶対しないというわけではないですよね？最終手段の位置づけとしてください」)。

1. **切る回数が少ないほう**を採る。切らずに済む選定があれば、歩く・運ぶ点が増えてもそちらを採る
2. 切る回数が同じなら、**本当の合計点が低いほう**を採る
3. どちらも切るときだけ切る(切ること自体は禁止しない)

**プロテックは別の考え方です**(「プロテックのカット前提とは別の考え方とも理解してください」)。
プロテックは製品幅に合わせて切るのが決まりなので、この比べ方に入れません(そのまま疲労度の選定を採る。
プロテックの選定はもともと疲労度を使いません)。ここで数える「カット前提」は、通常の選定で幅が足りないときの
**最後の手段としての幅広カット**のことです。

```
本当の合計点 = 歩く(サイズごとに1往復)
            + 運ぶ((面積 + 手間) × 枚数。補填板も1枚ずつ)
            + 切る(記録された丈カット × 切る枚数 + カット前提の板は全数の幅カット)
```

- 同じなら疲労度の選定を採ります。選定ログに両方の点と、どちらを採ったか・その理由が出ます
- アングルも同じ(切らないほうを先に。どちらも切る/切らないなら点で比べる。切るなら1回50点)。製品丈に足りない選定は採りません
- 比べるのは「通常の選定」と「疲労度の選定」の2つです。両方とも切るときに、別の組み合わせ(候補変更の「要カット0」など)なら切らずに済むことはありえます

実データ(共有マスタの写し、ボード544通り・アングル106通り)での比べ:

| | 疲労度OFF | 疲労度ON(直す前) | 疲労度ON(直したあと) |
|---|---|---|---|
| ボード 切る選定(拠点 L1 / HVC / LVC) | 55 / 55 / 55 | 116 / 112 / 155 | **31 / 33 / 40** |
| ボード 板の枚数(L1) | 4761 | 5387 | **4821** |
| アングル 切る選定(どの拠点も) | 14 | 24 | **0** |
| 疲労度ONが通常より切る回数が多い結果 | ― | あり | **0通り** |
| 疲労度ONが通常より点が高い結果 | ― | あり | 各拠点1通り(切らずに済むぶん運ぶ。最終手段の考え方どおり) |

## 7. 在庫考慮と合わせたとき(VER4.8.67)

現場の声:「在庫加味が正しく動くか(在庫が少ないものをよけているか)、疲労度と在庫を合わせた場合に正しく動くか」

**点検したら、在庫考慮は「在庫のある板を先に並べる」だけでした。** 選定は「1枚で覆える板」から順に探すので、その段の候補が
在庫薄だけだとそれで決まり、在庫のある板を使う次の段まで進みません。通常の選定がふつうに選ぶ板を在庫薄にして試すと、
544通り中289通りで在庫薄を使っていました(外せば全部、在庫のある板だけで選べた)。疲労度と合わせたときは在庫を見ていませんでした。

**これから(在庫考慮ON)**

1. **先に在庫薄の板を外して選ぶ**(現場で了承)。外して選べれば、それを採る
2. 外すと選べないとき(下用・上用が空になる、幅に届かない、狭幅の並べ方に落ちる、プロテックの確定値が取れない)だけ、在庫薄も入れて選ぶ。
   選定ログに、使った在庫薄の板を出す
3. **疲労度もONなら**、外した板の中で通常の選定と疲労度の選定を比べる。比べる順は
   **在庫薄の枚数 → 切る回数 → 合計点**。在庫薄をよけると切ることになっても、よけるほうを採る
   (「両方onの場合在庫がなければ切るしかないので仕方がない」)

| 通常の選定がふつうに選ぶ板を在庫薄にしたとき(544通り) | 在庫薄を使った | 切る回数の合計 |
|---|---|---|
| 在庫考慮ON(直す前) | 289通り | 73 |
| 在庫考慮ON(これから) | **0通り** | 156(在庫が無ければ切る) |
| 在庫考慮ON + 疲労度ON(これから) | **0通り** | **81**(切らずに済むものを先に) |

- 在庫薄の印は、かんばん(看板_*)の「欲」が〇で、どの看板にも「不」の〇が無いサイズ。種別・幅・丈で突き合わせる
- **確かめられていないこと**: 実際のかんばんのサイズの書き方(幅×丈の順か)。丈×幅の順で書かれていると印が付きません

## 8. プログラムの場所

| 何 | 場所 |
|---|---|
| 式と決め打ちの値(距離・面積・長さ・カット・手間) | `packaging_tool/angle_service.py` の `fat_*`・`FAT_*` |
| ボードの見積もりと合算 | `packaging_tool/board_scoring.py` の `estimate_cut_fatigue`・`width_limit`・`total_fatigue` |
| カット前提の点 | `packaging_tool/board_selection_narrow.py` の `wide_cut_fatigue` |
| アングルの点 | `packaging_tool/angle_service.py` の `_agl_fat_score`(棚ごとの距離は `location_service.build_angle_fatigue_map`) |
| 棚検索の合計疲労度 | `packaging_tool/layout_session.py` の `show_selection`(運ぶぶんは `location_service.carry_board_score`・`carry_angle_score`) |
| 丈カットを決める唯一の箇所(ボードMAP・実績保存) | `packaging_tool/board_selection_algorithm.py` の `recalc_length_cut_info`(切断依頼は配置とカット前提の印から作る `reports.get_cut_size_info`) |
| 在庫考慮と疲労度の組み合わせ(ボード選定の入口) | `board_selection_algorithm.select_boards` |
| できあがった選定で比べる | ボード: `board_selection_algorithm.actual_fatigue`・`auto_select_lowest_fatigue` / アングル: `angle_service.angle_result_fatigue`・`select_angles_lowest_fatigue` |
