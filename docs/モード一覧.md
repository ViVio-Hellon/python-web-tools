# モード一覧

資材選択は**入力によって挙動が変わります**。何がどう変わるのかを1か所に
まとめます。現場からの「なぜこの結果になったのか」に答えるとき、まずここを
読んでください。

VBA原文(`総合ツール` の `MaterialMasterForm` ほか)と突き合わせた結果も
併記します。**思想が食い違っているものは「差」の欄に書きます。**

---

## 全体像

モードは大きく3つの層に分かれます。層が違うものは同時に効きます。

| 層 | 何で決まるか | 誰が決めるか |
|---|---|---|
| **受注の性質** | 引いたロット・受注の中身 | 自動(人は変えられない) |
| **包装仕様NO** | 受注の包装仕様NO | 自動(1P0113だけ手で強制できる) |
| **選び方の好み** | 利用者が押す | 人(押しっぱなし) |

---

## 1. 受注の性質で決まるもの

### EX受注

| | |
|---|---|
| 決まり方 | 仕掛受注の `EX_輸出区分` が空でない |
| 変わること | 帯に `EX` が出る / 倉庫送信で**発注コード・単位・発注数を空で送る** |
| こちら側 | `lot_service` が `is_ex` を立て、`work_context` と選定セッションが持つ |
| VBA | `SetExOrder` / `g_SendRows(r).isExOrder` |
| 差 | **なし** |

EXの実データは別の職場から届き、そちらが優先されます。こちらからは
「EXである」と分かる合図(品名 `EX`)だけを送ります ── 中途半端な値を
入れると、届いた側の突き合わせで混乱するためです。

VBAの `frmSendConfirm.btnSend_Click` も、EX行だけ発注数の検証を飛ばして
空欄で送っていました。ここも同じです。

---

## 2. 包装仕様NOで決まるもの

**4つあります。** どれも受注の包装仕様NO(`lblOdr(1)`)を見ます。

### 1P0113(裸梱包)

| | |
|---|---|
| 決まり方 | 包装仕様NO = `1P0113`、**または**「1P0113強制」トグルがON |
| 変わること | パレットもボードも使わない。溝切角材と松板だけで組む |
| こちら側 | `special_packaging.is_1p0113` / `force_1p0113` |
| VBA | `Apply1P0113Mode` / `m_force1P0113` |
| 差 | **なし**(強制トグルの扱いも同じ) |

資材は `松板角材` テーブルから寸法帯で引きます。松板の丈(A値)は製品丈で
4段階に分かれます(949以下→製品丈 / 1800以下→950 / 2400以下→1600 / それ以上→2330)。

### プロテック(1P1216 / 1P1125 / 1P1211)

| | |
|---|---|
| 決まり方 | 包装仕様NO がこの3つのいずれか |
| 変わること | ボード種別が「プロテックボード」に切り替わる。**上用は下用と同じボードを強制**。幅は**製品幅基準・マイナスのみ・超過禁止** |
| こちら側 | `special_packaging.protec_state` → `ProtecState(is_protec, is_1p1216)` |
| VBA | `CheckAndSetProtecMode`(`cond2`)/ `mIsProtecMode` |
| 差 | **なし** |

**`1P1216` だけ許容が違います**(コーミ金属)。幅の許容はマイナス10mm、
それ以外のプロテックはマイナス80mmです。

かつてVBAは「納入先に `ｶ)ﾏﾂｼﾀｼﾖｳﾃﾝ` を含む」も条件に入れていましたが
(`cond1`)、**廃止済み**です。こちらも移植していません。

### 1P1185(タイト限定)

| | |
|---|---|
| 決まり方 | **4つすべて**を満たすとき(AND) |
| | 包装仕様NO = `1P1185` |
| | 取引先名称に `ﾅﾒｶﾜｱﾙﾐ` を含む |
| | 製造板幅 が 1242〜1249 |
| | 製造板丈 が 1242〜1249 |
| 変わること | パレットサイズを固定値で決め打つ |
| こちら側 | `special_packaging.check_1p1185_mode` |
| VBA | `CheckAndSet1P1185Mode` |
| 差 | **なし**(4条件とも一致) |

**寸法が条件に入っている唯一のモード**です。ロットを引き直して寸法が
変われば、同じ包装仕様NOでも入ったり外れたりします。

### 上下共用(ザラ板など)

| | |
|---|---|
| 決まり方 | 使用保護材がアングル以外に確定したとき |
| 変わること | アングルの欄を出さない。上用キャンバスを隠し、上下で同じボードを使う |
| こちら側 | `SelectionPresenter.is_shared_board_mode` |
| VBA | `m_lastHosozai` / `ShowAngleControls` |
| 差 | **画面上の扱いだけ広い**(下記) |

**プロテックも画面上は上下共用として扱います。** 上下とも同じボードを
使う点で同じだからです ── ただし**選定アルゴリズムでは別の分岐**で、
プロテックは許容幅での判定が要ります。画面の都合と選定の都合を混ぜない
よう、`selection_flags` は `is_protec_mode` を個別に渡しています。

## 3. 利用者が押して切り替えるもの

こちらは**押しっぱなしのモード**です。ロットを切り替えても解除されません。

### 疲労度優先

| | |
|---|---|
| 決まり方 | 利用者が押す(帯にチップが出る) |
| 変わること | 選定が「取り出す手間」を加味する。距離と面積(と本数)でスコア化 |
| こちら側 | `SelectionSession.fatigue` |
| VBA | `mFatigueMode` / `mFatigueMapLower` `mFatigueMapUpper` |
| 差 | **なし**(式は `modFatigueCore` の統一式と一致) |

**効いていることが画面のどこにも現れない**ので、帯にチップを出しています。
在庫考慮は候補一覧に「(在庫考慮)」と出るため、そちらには出しません
(同じものを2か所に出さない)。

### 在庫考慮

| | |
|---|---|
| 決まり方 | 利用者が押す |
| 変わること | 在庫が薄いボードの点を下げる(看板マスタの「欲」を見る) |
| こちら側 | `board_scoring` の `stock_aware` |
| VBA | 同名の分岐 |
| 差 | **なし** |

### 1P0113 強制

| | |
|---|---|
| 決まり方 | 利用者が押す |
| 変わること | 包装仕様NOに関わらず 1P0113 として扱う |
| こちら側 | `force_1p0113` |
| VBA | `m_force1P0113` |
| 差 | **なし** |

## 4. モードではないが、挙動が変わるもの

区別が要るので並べておきます。**これらは「モード」と呼びません。**

| | 何か | なぜモードでないか |
|---|---|---|
| 狭幅パレット | 選定がその経路を通ったかの**結果** | 人も受注も選べない。選定の答えとして決まる |
| カット前提 | ボード1枚ごとのタグ | 画面全体の挙動は変わらない |
| 候補変更(敷き詰め) | 選定の**別経路** | 押すたびにA→B→Cと回る。現行の選定・配置には触らない |
| サイズ指定(資材展開) | 製品サイズの**入口** | 下記 |

### サイズ指定について

「サイズ指定」という名前のモードはありません。製品サイズの入り方が
2通りあるだけです。

| 入口 | 何が起きるか |
|---|---|
| **資材展開**(ロット検索) | 製造板幅・板丈を製品サイズ欄に入れて資材選択へ移る |
| **手で打つ** | 製品サイズ欄に直接入れる |

**どちらも「セット」までは押しません**(VBA `Page1_OnBtnHBClick` と同じ)。
パレットに収まるかの検証(回転の要否を含む)は利用者が自分で行います。

ただし**1P1185 は製造板幅・板丈を条件に持つ**ので、どちらの入口で
どの寸法が入ったかによって、モードに入ったり外れたりします。

---

## 突き合わせの結論

**判定条件はすべて一致していました。** 移植漏れ・条件違いはありません。

違うのは次の2点で、どちらも意図的です。

1. **上下共用の画面上の扱い** ── プロテックも上下共用の一種として
   上用キャンバスを隠します(製品幅を大きく超えるボードを超過禁止の枠へ
   配置しようとして静かに失敗する不具合があったため)。選定側の分岐は
   VBAと同じく別のままです
2. **プロテックの `cond1`(納入先)** ── VBA側で廃止済みの条件なので
   移植していません
