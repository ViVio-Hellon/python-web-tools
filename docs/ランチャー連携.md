# ランチャー連携(業務ツール統合ランチャー)

「ランチャー連携 要件定義」の **3. 各ツール側への依頼** と **10. 起動完了の確認** に、
総合ツールとして答えるページです。**統合ツール(all-tools 1.2.0)と同じやり方に揃えています**(→ 8)。

- 相手: 業務ツール統合ランチャー(`python-business-tools-launcher`。1.6.4 と 1.7.0 の作りで確かめた)
- 約束: ランチャーは**ツールごとの分岐を持たない**。起動ファイル・`config/app.json`・
  起動ファイルの隣の `stop.bat`・`/api/health` だけを見て扱いを決める。
  ツールの中の流れ(exe → Python → 画面)は、このツールが引き受ける。

---

## 1. 起動方法(3.1・3.3・3.4)

ランチャーに登録してよい起動ファイルは次の3つです。**どれもランチャーからそのまま実行できます。**

| 起動ファイル | 何が起きるか(中の流れはツール側の責任) | 画面 | 使うとき |
|---|---|---|---|
| **`梱包資材総合ツール.exe`**(デスクトップ版) | exe(Tauri)→ Python(`bridge.py`)を子として起こし、標準入出力でやりとり。**ポートを使わない** | アプリ自身の窓 | exe を配った PC |
| **`Start.vbs`**(ブラウザ版) | `pythonw start_app.py` を起こして**すぐ戻る**(コンソールなし・**引数は渡さない**)→ 127.0.0.1 で待ち受け → ふだんのブラウザに画面 | ツールが開く | ブラウザ版の PC |
| `start.bat`(ブラウザ版・診断用) | `python start_app.py %*`。止まるまで戻らない。経過と失敗の理由をコンソールに出す | `--no-browser` を渡すとランチャーが開く | **ランチャーには勧めない**(下) |

- **1台の PC にはどれか1つを登録**してください。exe と Start.vbs は同じ `config/app.json` を読むので、
  アプリIDが同じ(`nlm.packaging-tool`)になり、ランチャーは2つ目を保存できません。
- 現場・資材のどちらで開くかは、**この端末に許されたモード**(アクセス権限マスタ)で決まります。
  ランチャーの設定でモードを分ける必要はありません。ただしポートは違います(→ 5)。

### start.bat を勧めない理由・Start.vbs が引数を渡さない理由

ランチャーは、起動ファイルが引数を渡すとき(`start.bat`)は `--no-browser` を付けて起動し、
**自分の画面**を開きます。止めるときは**その画面を先に閉じ**(閉じなければ 10 秒で強制)、それから
ツールを止めます。保存していない図(配置編集・保管位置マップ)があると:

1. 画面を閉じようとすると「このサイトを離れますか?」が出て、誰も答えないまま 10 秒で強制的に閉じられる
2. ツールは「保存していない変更があります」で止まるのを断るが、**図を保存する画面はもう無い**

`Start.vbs` は引数を渡さないので、画面はツールのもの(ふだんのブラウザ)で、ランチャーは閉じません。
止めるときは**画面を残したまま**断れるので、その場で保存できます。VER4.7.0 で一度 Start.vbs に引数を
渡すようにしましたが、この理由で VER4.7.1 で戻しました(統合ツールも渡していません)。

それでも画面が強制的に閉じられたとき(ブラウザが落ちた・`start.bat` を登録した)のために、
**「閉じます」の合図なしに画面が消えたら、保存していない図があるうちは自動終了しません**(VER4.7.1)。
ランチャーのボタンでもう一度画面を開けば、図はそのまま残っていて保存できます。

## 2. 起動して落ちないことの確認(3.2)

| 確かめたこと | どこで | 結果 |
|---|---|---|
| exe を起動し、窓の画面が Python から届く・どのプロセスもポートで待ち受けない | GitHub Actions(Windows)・この開発環境(Linux) | OK |
| exe を**もう一度**起動すると、窓を出さずにすぐ終わる(戻り値 0)。1つ目は動いたまま | 同上 | OK |
| exe の窓に「閉じて」(WM_CLOSE)と頼むと、×と同じ確かめを通って**自分で**終わる(戻り値 0、Python も残らない) | GitHub Actions(Windows) | OK(`scripts/desktop_smoke.py`、毎回) |
| ブラウザ版を起動し、ランチャーのコードで登録・起動確認・停止 | この開発環境(ランチャーの `tool_registry` / `health` / `process_manager` をそのまま使用) | OK(→ 4) |

確かめていないこと: Windows の実機で、ランチャーの画面から押す一連の操作(wscript 経由の Start.vbs、
保存していない図があるときの exe の確かめの窓)。

## 3. 終了方法(3.5)

| 止め方 | 動き |
|---|---|
| 画面の［終了］ | 保存していない図・実行中の処理があれば訊く。「終了する」なら止める |
| デスクトップ版の窓の × | ［終了］と同じ確かめ |
| ブラウザ版のタブを閉じる | 保存していない図があれば先に訊く。閉じたら 8 秒で自動終了。無通信 90 秒でも終わる(保存していない図があるうちは終わらない → 1) |
| `stop.bat` | **ブラウザ版だけ**を止める(下の表)。`--force` で保存せず・中断してでも止める。`--status` は見るだけ |
| `POST /api/shutdown` | ブラウザ版の停止要求。トークン(`X-Tool-Token`)が要る。ロックファイルに入っている |
| ランチャーの［ツール停止］ | 次の 4 |

**どの止め方も、保存していない図・実行中の処理があれば止めずに理由を返します**(HTTP 409)。
理由は `running`(一覧)と `message`(文)の両方に入れています。ランチャーと `stop.bat` は `running` を読みます。

```json
{"stopped": false, "reason": "unsaved",
 "running": ["保存していない変更(簡易在庫の保管位置マップ)"],
 "message": "保存していない変更があります(簡易在庫の保管位置マップ)。保存せずに終了しますか?"}
```

`stop.bat` の戻り値(VER4.7.1 から。統合ツールの `process_manager.py` と同じ値):

| 戻り値 | 意味 |
|---|---|
| 0 | 止めた/もともと動いていない |
| 1 | 止められなかった(応答しない・このツールか確かめられない)、または**デスクトップ版(exe の窓)が動いている** |
| 2 | 止めなかった(保存していない図・実行中の処理がある)。`stop.bat --force` で止める |

- **デスクトップ版は `stop.bat` では止めません**(統合ツールと同じ)。窓の × か画面の「終了」で閉じてください
  (閉じるときに保存していない図・実行中の処理を訊くため)。以前の `stop.bat` は、デスクトップ版が動いていても
  「起動していません」と出して 0 を返していました。いまは中の Python が置く印
  (`%LOCALAPPDATA%\PackagingTool\runtime\desktop.json`)を見て、「デスクトップ版が動いています」と 1 を返します
- **プロセス名で一括に止めることはしません。** `stop.bat` はまず `/api/shutdown` で頼み、応答が無いときだけ
  ロックファイルに記録した PID を使います。その前に、その PID のコマンドラインにこのツールの置き場所が
  入っていることを確かめます(`process_manager.py`)

## 4. ランチャーから止める(3.6)

ランチャーの［停止方法］は **auto のまま**で止まります。総合ツール専用の止め方(`launcher_stop.bat`)は
作っていません(統合ツールも同じ。→ 7)。

| 起動ファイル | ランチャーがすること | 保存していない図・実行中の処理があるとき |
|---|---|---|
| exe | 窓に「閉じて」(WM_CLOSE)と頼む = × と同じ | ツールの窓に確かめが出る(ランチャーが窓を前に出す)。ランチャーの［ツール停止］には「強制終了する」が出る |
| Start.vbs | 隣の `stop.bat` → `POST /api/shutdown` → PID(照合してから)。画面は閉じない | 止めずに「保存していない変更(…)」と出し、「強制終了する」が出る。画面は残るのでその場で保存できる |

ランチャーのコード(1.7.0)で確かめた結果(この開発環境、ブラウザ版):

```
[OK] 登録で読む値: app_id=nlm.packaging-tool / 表示名=梱包資材総合ツール / ポート 8713
[OK] Start.vbs の起動引数の自動判定は空(画面はツールのもの・ランチャーに先に閉じさせない)
[OK] 起動完了(ready)を確かめた(1.4秒)
[OK] 停止用のトークンをツールのロックファイルから拾えた
[OK] stop.bat(process_manager)の戻り値 2 = 止めなかった: 止めませんでした: 保存していない変更(簡易在庫の保管位置マップ)
[OK] 保存していない図があると止めない: busy=['保存していない変更(簡易在庫の保管位置マップ)']
     (VER4.6.5 までは「実行中の処理があります: (不明)」と出ていた)
[OK] 「強制終了する」で止まった → ツールが自分で終わった(戻り値 0)・ロックファイルが片付いた
[OK] ふだんの［ツール停止］で止まった(戻り値 0)
```

デスクトップ版(Linux で作った exe)を動かしたまま `stop.bat` と同じもの(`process_manager.py --all`)を流すと、
「デスクトップ版(exe の窓)が動いています。stop.bat では止めません」で戻り値 1。exe を閉じると印も消え、戻り値 0。

## 5. 起動完了の確認(10)

### ブラウザ版: `GET http://127.0.0.1:<ポート>/api/health`

```json
{"app_id": "nlm.packaging-tool", "display_name": "梱包資材総合ツール", "ready": true, "stage": "起動完了",
 "stage_key": "done", "pid": 1234, "port": 8713, "mode": "field", "version": "4.7.1",
 "app_root": "C:\\業務ツール\\総合ツール"}
```

- **`app_id` が `nlm.packaging-tool` で、`ready` が `true` なら起動完了**。`ready` が `false` の間は
  `stage` に今の段(「準備しています」など)が入る。ランチャーの進み具合の窓にそのまま出せる。
- トークンは要らない(業務データを返さない)。`app_root` はランチャーが止める前の照合に使う。
- ポートは**端末のモードで違う**: 現場 **8713**、資材 **8723**。使われていれば 3 つ先まで繰り上がる
  (現場 8713〜8716、資材 8723〜8726)。ランチャーは設定と違うポートで動いていても見つけるが、
  資材の端末ではランチャーの［ポート］を **8723** にしておくと最初から合う。
- いま実際に使っているポートと PID・停止用のトークンは `%LOCALAPPDATA%\PackagingTool\runtime\field.lock`
  (資材は `material.lock`)に書いてある。

### デスクトップ版: ポートが無い

- ランチャーは**窓が出たこと**で起動を確かめる(ランチャーの［画面］= アプリの窓)。
  窓はすぐに出て、中に「起動しています」→ 準備ができたら画面、の順に出る。
- **ランチャーの［ポート］は空にしてください**(統合ツールも同じ)。［＋ ツールを追加］で exe を選ぶと
  `config/app.json` の 8713 が入りますが、デスクトップ版はそこで待ち受けません。そのままだと、
  ランチャーは起動確認が答えないと見て、**起動から 90 秒の間は［ツール停止］が「窓を閉じてもらう」
  手ではなく PID の手に回り**、90 秒たつと「起動を確かめられない」の障害記録を書きます。
  exe とブラウザ版が同じ `config/app.json` を使うので、ツール側では分けられません。

## 7. ランチャー 1.7.0 の「ツール側の入口」について

ランチャー 1.7.0 は、起動ファイルの隣に `launcher_check.bat`(起動確認)・`launcher_stop.bat`(終了)が
あれば、ランチャーの推測(設定のポートの `/api/health`・窓の検出・停止方法の自動選択)より優先して使います。
**総合ツールは置いていません**(統合ツール 1.2.0 も置いていない)。置かなくても、上の 4・5 のとおり
ランチャーの推測で起動・停止できます。

置くときに考えること(統合ツールと揃えて決める):

- 入口を置くと**窓の検出を使わなくなる**ので、exe を選んだ PC では `launcher_stop.bat` が exe を止め、
  `launcher_check.bat` が exe の起動を答える必要がある。いまのデスクトップ版は外から止める口を
  窓の × しか持っていない(`stop.bat` は止めない)
- 入口があれば、5 の「exe の行はポートを空にする」は要らなくなる
- `launcher_stop.bat` が 0 以外を返すと、ランチャーはすぐ理由を出す(いまは `stop.bat` の戻り値を見ずに
  20 秒待ってから `/api/shutdown` に進み、そこで理由を出す)

## 8. 統合ツール(all-tools 1.2.0)との揃え

| 項目 | 統合ツール | 総合ツール |
|---|---|---|
| exe の止め方 | 窓に WM_CLOSE(× と同じ)。打ちかけを置いてから終わってよいか訊く | 同じ(保存していない図・実行中の処理を訊く) |
| Start.vbs の引数 | 渡さない | **渡さない**(VER4.7.1 で揃えた) |
| ランチャーに勧める起動ファイル | exe / Start.vbs(start.bat は勧めない) | 同じ |
| exe の行のポート | 空にする | 同じ |
| `stop.bat` の戻り値 | `process_manager.py` は 0 / 1(デスクトップ版が動いている)/ 2(止めなかった) | 同じ値(VER4.7.1)。総合ツールの `stop.bat` はこの値を**そのまま**返す |
| `stop.bat` でデスクトップ版 | 止めない。知らせて 1。窓を前に出す | 止めない。知らせて 1(窓は前に出さない) |
| 停止の断り(409)の `running` | 理由が入る | 同じ(VER4.7.0 から) |
| `/api/health` の `app_id`・`ready`・`app_root`・`display_name` | ある | ある |
| `launcher_check.bat`・`launcher_stop.bat` | 置いていない | 置いていない |
| 外から止めるとき、画面の打ちかけ | 開いている画面に「打ちかけを置いて」と頼んでから止める | 頼まない。保存していない**図**はサーバが持っているので 409 で断る。入力欄に打ちかけの文字(コメントなど)は、止まると送れなくなる(画面には残る) |
